# System Design

Use this when the present need is a system or architecture decision: defining the system boundary, the contracts (interface, data, permission, provider, trust, failure), runtime/module shape, or planning compatibility, migration, or build slices.

| Need | Read |
|---|---|
| discover the current system; define interface, data, tenant, trust, provider, or failure contracts | `architecture-and-contracts.md` — Boundaries and contracts |
| choose runtime/module shape; plan compatibility, migration, recovery, and build slices; or pick the low-cost baseline | `architecture-and-contracts.md` — Decisions, baseline, and plan |

Some mechanisms used here (fact states, reuse/extend/replace/new, evidence inventory) are defined once in `references/methods.md`.
