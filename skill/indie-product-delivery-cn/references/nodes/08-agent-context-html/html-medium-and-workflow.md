# 以 HTML 作为 Agent 上下文与项目看板

当 HTML 工作面有助于理解项目时，构建可在浏览器中打开的项目文档，让创始人、开发者或接手的 agent 无需从聊天与源码树中重建项目即可理解。将落地看板作为以证据为支撑的快照，并在适合读者时使用聚焦子页面或其他文档格式。

## 默认看板目标与覆盖范围

当项目在 `docs/` 下使用 HTML 看板时，其目标是为新加入的人或 agent 提供直接证据，以便快速理解并启动项目。以完整台账风格维护看板：覆盖核心数据库表与核心业务字段、重大路由/动作、能力、关系、架构、状态、风险、决策与发布证据。不要用低价值的 UI 琐事（例如按钮尺寸）填充看板，除非某个具体值是有意义的设计契约。

| 读者任务 | 有用的 HTML 形式 |
|---|---|
| 对比方案或视觉方向 | 对齐的列、共享标准、内联权衡与清晰的选择状态 |
| 理解架构或代码路径 | 标注的方框与箭头、高亮的热路径与到入口点的直达链接 |
| 评审实现或发布 | 状态与证据卡片、带注释的变更导览、风险、检查与确切身份 |
| 检视设计系统 | 可用的 token、组件变体、响应式状态与可复制的值 |
| 调整动效或交互 | 一个带有控件与重置行为的小型可用原型 |
| 监控项目事实 | 一个可导航的看板，覆盖产品、架构、契约、状态、证据与历史 |

## Workflow

1. 建立持久文档契约：目标读者与决策、维护负责人、现有模板/术语、事实来源、未知项/冲突、披露边界、必需章节与读者测试可用性。对完整草稿、章节打磨、写作审计与读者测试记录使用共享的写作与质量协议。
2. 检视完整的相关证据面：代码、测试、配置、迁移/schema、路由或 OpenAPI、维护中的产品文档、运行时安全的观察，以及经批准的外部来源。当断言冲突时，按以上顺序优先取用。
3. 在动笔之前先构建来源清单。清点范围内的能力、路由/动作、schema、数据库实体与有证据的字段、关系、策略、架构组件、决策、风险与路线图记录。将此清单作为覆盖清单。渲染每一项，或标记为 unknown，或附理由排除。
4. 用内容模型组装看板事实。为每条重大断言记录证据路径或显式的 `unknown`；保留 ID、字段名、命令、版本、路由与注意事项，使验证成为可能。不要用一两个示例性样例替代可用的完整台账。
5. 按以下阅读顺序组织文档：
   - **项目摘要** —— 产品是什么、服务谁、当前问题、承诺结果、首次成功、商业状态与定价。
   - **产品与交付** —— 能力地图、旅程/MVP 边界、验收与验证，加上 shipped、in-progress、candidate、deferred、blocked 与 unknown 的工作。
   - **架构** —— 用户到系统/数据流、前端与后端职责、模块边界、集成、后台任务与恢复/失败路径。
   - **技术与契约** —— 技术栈与重大决策；数据库实体与字段；API/动作及其请求、响应、权限与失败语义。
   - **控制室** —— 发布/验证状态、决策记录、证据置信度、风险、阻塞项与排序后的下一步行动。
6. 让落地页以决策为导向：身份、发布边界、商业状态、能力摘要、首要风险、下一步行动、新鲜度，以及到每个主题页的链接。把字段级契约、完整 endpoint 行为、详细架构、验收台账与决策历史放到它们各自的主题页。
7. 为每个必需区域提供基于来源的内容或可见的 unknown 状态。不要仅因为项目尚无证据就省略定价、API、数据库或交付覆盖。优先使用完整台账而非示例样例：记录范围内每个有证据的路由、实体、字段、能力、风险与决策。
8. 保持每个当前状态页同步。每次 commit 或 push 之前，将最新源码与配置同看板对比并更新陈旧事实。对于重大发布、版本、迁移、事故、安全评审或里程碑，创建或更新本地活动页，包含日期/版本、变更范围、证据、影响与后续事项。不要在其中添加例行刷新或重复的当前状态叙述。
9. 应用视觉与交互参考。当用户提供参考站点时，检视其真实 DOM、计算样式、尺寸、断点、组件状态与交互，而不是凭记忆近似其氛围。忠实重构所选页面原型，同时将其主题替换为项目文档。在没有 JavaScript 的情况下仍保持核心内容可见。
10. 运行验证参考与默认 human 通道。将来源清单计数与渲染计数对账。在可用时用浏览器打开落地页及变更或高风险页面；对其余页面使用确定性检查。纠正缺失记录、溢出、嵌套网格碰撞、键盘陷阱、跨页漂移、误导性状态措辞、无支撑断言与通用填充。将渲染页作为整体阅读，删除重复章节开头、标题重述、每事实一卡的布局与其他模板残余。记录是否进行了独立读者测试，未做时声明其限制。

## 状态与证据纪律

- `shipped`、`done` 或 `validated` 需要直接的实现、部署、测试、配置或维护中的契约证据。
- `in-progress`、`partial`、`blocked`、`candidate`、`deferred`、`unknown` 与 `untested` 必须指明能让其推进所缺的证明、决策、依赖或动作。
- 将推断性断言可见地标记为推断。当来源不一致时，展示冲突并降低置信度，而非静默地选取某个版本。
- 让"实时"意指最新检视的证据快照。在没有现成数据源的情况下，绝不模拟实时遥测或自动进度更新。
- 排除凭据、token、原始个人数据、私有 payload 与漏洞利用细节。改为总结其契约或安全后果。

## 实现与交接

默认使用语义化 HTML、内联或本地 CSS、内联 SVG，以及最少的原生 JavaScript。除非现有项目或用户明确要求，否则避免远程运行时依赖、框架、远程字体与网络调用。

仅改颜色、字体或卡片样式并不构成参考驱动任务的完成。需匹配参考的信息几何：内容宽度、章节节奏、字号比例、导航、边框、圆角、间距、组件组合、披露模式、响应式过渡，以及 focus 或交互状态。

仅当其许可证或用户授权允许时才复用源代码或资产。否则以等价的视觉保真度独立实现所观察到的设计。

在最终回复中，说明已变更的看板、文档类型、所核查的证据与验证、已完成的写作审计、读者测试状态、可见的高风险未知项或读者理解风险，以及建议的下一步行动。不要将生成的 HTML 粘贴到聊天中。
