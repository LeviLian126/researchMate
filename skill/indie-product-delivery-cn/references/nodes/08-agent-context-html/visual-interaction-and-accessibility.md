# 视觉、交互与可访问性系统

把 HTML 作为信息的工作面，用于呈现难以在 Markdown 线性文档中理解的内容。以 [HTML Effectiveness](https://thariqs.github.io/html-effectiveness/) 作为默认前端参考：以让读者一眼看清其形态的方式渲染对照、流程、时间线、依赖地图、带注解的证据和状态泳道。让当前快照可直接打开，并通过普通的本地导航链接聚焦的专题页。

## 工作流程

选择与每种信息关系匹配的空间形态，重构所选 HTML Effectiveness 页面原型，然后只添加能改善导航或密度的交互，同时保留无 JavaScript 的阅读路径。

## 参考驱动保真

当用户提供参考网站并要求近似或一比一复刻时，将该站点视为实现规约，而非情绪板。

1. 在可用时用浏览器开发者工具检视真实页面。记录 DOM 层级、计算后的颜色、字体、字号与行高、最大内容宽度、水平内边距、小节间距、边框、圆角、阴影、网格轨道、响应式断点、溢出行为、焦点状态和交互状态变化。
2. 在构建之前识别匹配的页面原型：documentation index、implementation plan、feature explainer、report、flowchart、comparison、editor 或其他已演示的形态。复刻该原型的构成，而非把不相干的示例杂糅成通用 dashboard。
3. 建立紧凑的重构规约和共享设计 token。除调色板外还要匹配几何与行为：页眉、导航、阅读度量、标题节奏、图面、表格、disclosures、说明文字和移动端过渡。
4. 用项目事实替换参考的主题内容，同时保留其前端语法。不要止步于"颜色和卡片相似"。
5. 在桌面、受限桌面、平板和移动尺寸下，将渲染截图与参考对照。在交付前纠正对齐、比例、密度、换行和交互上的显著差异。

仅在许可证或用户授权允许复用时，才使用源码、字体、图标或其他资产。否则在匹配可见结果和行为的前提下，独立重构所观测到的前端。

## 默认 HTML Effectiveness 体系

以 `../assets/document-system.css` 作为实现基线。它是一份独立实现、已验证的样式表，源自对 HTML Effectiveness 文档示例的检视，已包含项目 board 组件所需的安全响应式行为。

当线上参考可用时，检视其 index 页面以获取导航与文档索引构成，`16-implementation-plan.html` 以获取计划、里程碑、图、对照、风险和问题，`14-research-feature-explainer.html` 以获取 disclosures、tabs、callouts、文件地图和 FAQ 行为。使用最贴近的原型；不要把所有模式堆到每一页上。

除非所选参考页面演示了另一个取值，否则保留以下检视所得默认值：

| 层级 | 默认值 |
| --- | --- |
| canvas | ivory `#FAF9F5`；paper-white 内容面；near-black `#141413` 文本 |
| accents | clay `#D97757` / dark clay `#B85C3E`；oat `#E3DACC`；olive `#788C5D`；低饱和度灰用于元数据 |
| typography | 系统无衬线正文，Georgia 兼容衬线标题，系统等宽用于契约和路径 |
| geometry | 居中 `1120px` 最大页面，`32px` 桌面侧边距，宽松小节节奏，`12–14px` 面板圆角，细 `#D1CFC5` 边框 |
| index 原型 | 约 `62px` 的衬线展示标题，pill 形文本导航，宽度允许时为三栏示例/索引网格 |
| detail 原型 | 约 `38px` 的衬线页面标题，约 `26–27px` 的小节标题，prompt/summary 块，白色图面，密集台账，disclosures 和本地导航 |
| 响应式行为 | 约 `880–900px` 处折叠 summary 与 mock 网格；约 `780px` 处折叠密集行布局；约 `640px` 处使用单栏阅读顺序 |

当 index 与 detail 原型需要不同标题比例时，添加页面级类。保留克制的文档气质：不要渐变、玻璃效果、色块、装饰插画、远程字体导入、通用营销 hero，或一面墙的雷同浮动卡片。让排版、对齐、分隔线和留白来阐释层级。色彩用于强化文本标签和标记；它本身不承载状态含义。

## Board 构成

落地页保留紧凑摘要：项目名、当前发布/交付状态、关键决策或风险、证据新鲜度，以及最重要的下一步行动。其后接文档索引，列出每个专题页及其证据/状态责任。子页面需重复紧凑、一致的全局导航，并始终提供回到当前快照的直接路径。

把这些页面当作专业工程文档，而非预告。使用所选原型的标题比例与间距，再用密集台账、锚点小节、图、定义、源码路径和完整契约表格填满。不要把完整的文档任务变成稀疏的摘要卡片，让读者从源码中拼凑缺失细节。

| 信息 | 首选形态 |
| --- | --- |
| 项目、受众、承诺、定价 | 简洁事实台账或对照表 |
| 能力状态与 MVP 边界 | 带标签的状态泳道加验收/证据台账 |
| 顺序或路线图 | 时间线，带 shipped、in-progress、candidate 和 blocked 标记 |
| 前端/后端/数据流 | 带标签的方框和箭头；标注交接、归属和失败路径 |
| 技术栈与决策 | 紧凑决策表，含影响后果与复核触发条件 |
| 数据库实体 | 关系图加可展开的字段契约表 |
| API/actions | endpoint 索引加可展开的 request/response/error 契约 |
| 风险与下一步行动 | 严重度/影响台账加简短的优先级行动队列 |

使用 `<details>` 和 `<summary>` 让长页面保持可导航。当某节会让读者在到达下一个决策前过多滚动时，将次要细节折叠进可折叠 disclosure 中：冗长的技术解释、完整台账、字段级数据库与 API 契约、route/endpoint 主体，以及恢复流程。把摘要、状态、证据和一行式决策保留在折叠体之外，以便读者决定是否展开。一个打开时大部分 toggle 收起的页面会隐藏当前状态；一个在已经过长时仍什么都不折叠的页面则辜负了 board。首屏应展示当前真相，每个 toggle 按需揭示更深层。

## 渐进式交互

核心事实必须在禁用 JavaScript 时可用。仅当小段 vanilla-JavaScript 交互能让 board 更快用时才添加：

- status/category 筛选器，不隐藏当前选中项或证据；
- 锚点目录与滚动位置指示；
- focus/hover 联动的架构节点和 details 面板，并配有点击和键盘等价操作；
- 命令、route 或 action 列表的复制控件；
- 可排序/可展开的密集台账，且默认顺序仍有意义。

不要仅因为某交互可行就添加。没有可访问默认值就不要把项目状态藏到 tabs 后，不要用 hover 作为唯一揭示内容的方式，也不要依赖远程 API 完成首屏渲染。

## 布局安全与可访问性

- 使用语义化地标、单一明确页面标题、逻辑化标题、可见焦点、描述性链接文本、标签，以及内联 SVG 标签/替代。
- 尊重 `prefers-reduced-motion`；除非能澄清状态变化，否则避免动效。
- 窄屏下保留阅读顺序。让表格、代码、路径和契约在受限容器内滚动或安全换行；不要把它们缩成不可读文本。
- 在桌面、受限桌面、平板和移动宽度下测试粘性重叠、长标签、地图可读性、表格溢出和键盘可达性。
- 把嵌套布局当作独立的响应式状态。页宽下工作的三栏或四栏流，在半宽卡片内必须变成两栏或纵向轨道；绝不要用固定的子元素最小宽度硬撑。
- 给 grid/flex 子元素应用 `min-width: 0`，并在序列换行时调整或移除连接箭头。
- 长文件路径、源码路径和反斜杠风格的 Windows 路径在狭窄表格单元格、卡片和 nav pill 内是布局隐患。确保承载路径的文本有 `overflow-wrap: anywhere`，路径密集的表格放在带 `overflow-x: auto` 的 `.scroll` 容器里；确认最长真实路径干净换行，而不是堆叠成纵向文本塔或把兄弟元素挤开。
- 把水平滚动预留给真正二维的表格、矩阵或图。普通卡片、对照、状态泳道和步骤流必须能重新排版，不出现截断文本、重叠箭头或嵌套滚动条。

## 让工件可检视、可移植

偏好自包含页面或小型静态站点，使用普通 HTML、CSS、内联 SVG 和最少 JavaScript。当脚本失败时，核心内容、导航和证据必须保持可用。用交互揭示细节、筛选密集台账、高亮路径或对照状态；不要把基本事实藏到 hover、动画或不透明的客户端应用背后。

存在仓库设计 token 与资产时优先复用。无现成体系时，选择克制的文档体系：可读的文本度量、强层级、清晰状态编码，以及足够长时间会话的对比度。装饰性新奇不得压过项目证据。保留键盘可达性、焦点可见性、语义化地标、表格关系、reduced-motion 偏好、移动端重排，以及打印或截图可读性。

## 页面目录与导航一致性

每个 HTML 页面——包括落地页、子页面和归档页——必须恰好包含一个 `<aside class="toc">` 目录块，紧跟页面导语/摘要之后、首个主内容小节之前。TOC 是新读者和 agent 的首个导航锚点：让读者无需滚动整页即可判断页面覆盖哪些主题、当前证据位于何处，也让 agent 在每次 commit 前用一次 grep 验证所有页面。

### 必需 TOC 契约

1. **存在性**：每个独立 HTML 页面必须有一个 `<aside class="toc">` 元素。落地页和归档页不豁免。若页面过短不需 TOC，应作为其父页面的小节存在，而非独立页面。
2. **统一标题文本**：
   - 英文（`.html`）：`<b>On this page</b>`
   - 中文（`.zh.html`）：`<b>本页目录</b>`
   - 禁止使用 `Contents`、`Table of Contents`、`本页导航`、`本页内容`、`目录` 等变体。统一措辞让读者在页面间建立稳定视觉预期，也让 agent 用 regex 确定性验证，而非逐页人工核对。
3. **锚点完整性**：TOC 中每个 `<a href="#anchor">` 必须对应正文真实 `id`。断开的片段链接是 board 信任失败。
4. **稳定位置**：TOC 紧跟导语/摘要之后、首个主内容小节之前；不要放到 footer 或藏进 disclosure。

### 为何此规则是硬约束

TOC 措辞漂移和缺失 TOC 是当前 board 最常见的两类一致性问题：英文版混用 `On this page` 和 `Contents`，中文版有四种写法——`本页导航`、`本页内容`、`本页目录`、`目录`——而部分归档和落地页根本没有 TOC。读者不得不在每页重新辨认 TOC 的位置和名称，agent 也无法用一条命令审计整站。统一措辞加强制存在性同时解决两个问题：每页都有 TOC，每页用相同名称，中英文一一对应。

### 跨页导航同步

新增 HTML 页面时，须同时更新所有兄弟页面的导航栏，使新页面可从每个相关页面到达：

1. **导航栏同步**：若新页面属于某子页面导航组（如 learn/ 下的子页面），新页面链接必须加到每个兄弟页面的子页面导航栏。漏掉任何一页都会使新页面不可被发现。
2. **标签一致性**：同一子页面的导航标签在所有页面上须一致（中文页面统一用中文标签，英文页面统一用英文标签）。例如 index 用 "切面分析"，则每个子页面导航须用 "切面分析"，而不是混用 "Flow analysis"。
3. **链接后缀一致性**：中文页面导航链接统一用 `.zh.html` 后缀；英文页面统一用 `.html`。语言切换链接为例外（指向另一语言版本）。
4. **验证清单**：新增页面后，逐个检查每个兄弟页面的导航栏中是否有新页面链接、标签是否一致、链接后缀是否正确，并确认每个页面（含新页面本身）都有满足上方 TOC 契约的 `<aside class="toc">` 块及统一标题文本。此步骤不可省略。

## 返回顶部控件

每个 HTML 页面——包括落地页、子页面和归档页——必须恰好包含一个返回顶部按钮,且全站设计一致。该按钮让读者无需滚动即可返回长页面顶部,统一的图标让 agent 在每次 commit 前用一次 grep 验证所有页面。

### 必需返回顶部契约

1. **存在性**:每个独立 HTML 页面必须有一个 `<button class="back-to-top" data-back-to-top hidden>` 元素,放在 `<script>` 标签之前。
2. **统一图标**:所有页面使用相同的内联 SVG 箭头图标。不要替换为其他字形、emoji 或文本标签。图标是控件的视觉标识,变化会破坏跨页信任。
3. **设计体系**:按钮遵循现有设计 token——hover 时 clay 强调色、paper-white 背景、`--g300` 边框、`999px` 圆角、`42×42px` 固定在右下角。CSS 放在共享的 `site.css`(或等效的 `document-system.css`)中,不是每页内联样式。
4. **行为**:按钮默认 `hidden`,读者滚动超过约 320px 后出现。点击平滑滚动到顶部。显示/隐藏逻辑放在共享的 `site.js` 中。
5. **无障碍**:按钮有 `aria-label="Back to top"`,可键盘聚焦且有可见焦点环,尊重 `prefers-reduced-motion`。

### 为何此规则是硬约束

长文档页面没有快速返回顶部的控件,读者被迫滚动整页返回。当每个页面使用不同图标或位置时,读者失去对控件位置的肌肉记忆。单一共享的图标、位置和行为——可通过 `grep -r 'data-back-to-top' docs/` 验证——同时解决两个问题:每页都有控件,每页使用相同设计,agent 可用一条命令审计整站。

## 流程页面的视觉呈现

当页面需要呈现业务流程、请求流或数据管道时，偏好空间化的流程图而非纯文本证据链。参照 HTML Effectiveness 的 `14-research-feature-explainer.html` 原型和 pipeline 模式：

1. **管道时间线**：使用纵向时间线（左侧连接线 + 编号圆环节点）；每步是带颜色编码的卡片，标注其步骤类型（intercept/approve/execute/inspect）。
2. **颜色编码**：红色 = intercept/失败路径，黄色 = approve/暂停，绿色 = pass/inspect，橙色 = execute/外部调用，灰色 = 中性/no-op。
3. **步骤卡片**：每个步骤包含标题、类型标签、描述、所经过的文件/函数名、数据库读/写标记，以及外部调用标记。
4. **子步骤**：用嵌套子步骤列表展开复杂步骤；每个子步骤携带自己的类型标签。
5. **全景预览**：在详细流程之前，用横向 chips 条展示整条管道，让读者先看到全貌。
6. **对照视图**：对于"有/无某机制"的对照，使用并排对照卡片布局。
7. **Effectiveness 说明**：每个流程之后，用橙色 callout 框解释关键设计决策为何有效。
