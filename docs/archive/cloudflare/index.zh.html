已归档的 Cloudflare 部署替代方案

本页面记录一个已废弃的托管方案，属于历史背景而非可执行建议。当前拓扑为 Vercel Hobby 加一个合并的 Render Free 服务。

已归档 · 非当前拓扑无公开部署证据可执行路径已移除 · 源码保留

历史边界

历史范围

拟议职责

曾考虑将 Cloudflare Workers 上的 OpenNext bundle 作为确定性浏览器端 Next.js demo 的第二主机。

不作为后端主机

该方案从未运行 Python FastAPI、Celery、dispatcher、Docling 或持久化工作流进程。这些职责需要后来选定的合并容器运行时。

历史证据：Worker bundle 通过了仓库端构建检查，但发布运行 #4 停止在提供商授权阶段。未验证任何 workers.dev 端点或公开 Cloudflare 部署。

归档组件台账

已废弃组件

组件历史角色证据当前处置
Cloudflare Workers + OpenNext浏览器端 Next.js demo 的重复主机。发布 #4 在提供商部署前失败。已废弃的 发布工作流、OpenNext 配置、Wrangler 配置和 npm 片段作为惰性源码记录保留在此。已被已上线的 Vercel 部署取代。无活跃的 Cloudflare 工作流、应用配置、npm 命令或部署依赖项。
Cloudflare R2早期的 S3 兼容对象存储候选方案。提供商兼容的配置名称和迁移期字面量因向后兼容性保留；未验证已激活的 R2 运行时。已选择 Supabase Storage 并有直接 PUT/HEAD/DELETE 证据。提供商中立的 S3 代码保留。
GHCR曾考虑用于 Python worker 镜像的中间注册表。冻结方案不需要已发布的镜像。Render 直接从仓库构建 Dockerfile。

决策依据

废弃决策

重复面Vercel 已在提供有界的公开 Web demo，因此第二前端主机增加部署数量而无后端证据。
运行时不匹配Python API、worker、dispatcher 和解析器工作负载需要容器主机。
额外授权和成本边界尝试的发布引入了另一个提供商权限路径，而对象存储已通过 Supabase 可用。
更小的冻结拓扑Render 直接仓库构建消除了对重复前端部署和中间镜像注册表的需求。

仓库状态

归档源码和遗留兼容性

2026 年 7 月 26 日废弃：可执行的 GitHub 工作流、应用级 OpenNext/Wrangler 配置、Cloudflare npm 命令和部署依赖项已从其活跃位置移除。精确的源码快照仅保留在此归档中，不能被 GitHub Actions 或 npm workspace 命令触发。

遗留环境变量别名和合约字面量（如 r2_object_key 或 r2_failure）因迁移和 API/数据兼容性保留。它们在当前拓扑中不选择 Cloudflare。任何后续清理必须审慎更新对应的迁移、schema、客户端和测试。
