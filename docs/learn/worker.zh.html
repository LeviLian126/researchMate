Worker . workers/ai-worker

ResearchMate AI Worker 是一个 Celery 应用,通过 3 个进程角色(组合部署)执行 6 个 durable tasks,分布在 5 个队列上。它负责文档摄取与解析、LangGraph evidence 工作流(含人在环审查)、Outbox 到 Celery 分发、RAGAS 评估、Lease 保护的删除以及 fault simulation。本页逐文件解析 workers/ai-worker/src/researchmate_worker/ 下的全部源码。

技术栈基础

驱动 Worker 的 8 个核心依赖

每张卡片说明该技术的通用职责,以及 Worker 中的具体用法。

Celery

分布式任务队列框架。celery_app.py 创建 Celery 应用,配置 task_acks_late=True、task_reject_on_worker_lost=True、worker_prefetch_multiplier=1、task_track_started=True。tasks.py 注册 6 个任务,设有有界 max_retries(3-8)和指数退避。组合部署时以 solo pool 单 worker 消费全部 5 个队列。

LangGraph

有状态图编排库。evidence_graph.py 构建 6 节点 StateGraph(plan、retrieve_and_extract、reconcile、human_review、synthesize、validate_and_commit),通过 Send 实现条件 fan-out。Checkpoint 持久化到 PostgreSQL,使用 PostgresSaver 和 JsonPlusSerializer(pickle_fallback=False)。interrupt() 原语暂停等待人工审查,不被 try/except 包裹。

RAGAS

检索增强生成评估框架。evaluation_scoring.py 使用 Ragas 0.4 collections API(Faithfulness 指标),后端为 OpenAI 兼容的 NVIDIA AsyncOpenAI client。Scorer 在 asyncio.run() 中运行,产出 MetricScore,通过阈值 0.8。三个确定性指标(schema_valid、citation_precision、evidence_recall)无需 LLM judge 即可计算。

Docling + pypdf

文档解析适配器。parsing.py 实现 DoclingDocumentParser,一个资源感知的解析器:为 PDF 保留 Docling 视觉管线,轻量文本提取时回退到 pypdf。DOCX 和 PPTX 通过 stdlib zipfile + ElementTree 解析,含 zip-bomb 防护。活跃后端由 pdf_parser_backend(pypdf 或 docling)选择。

Qdrant

向量数据库,用于 chunk 索引和检索。ingestion_service.py 调用 QdrantHybridStore.upsert_chunks() 将解析后的 chunk 投影到向量库。workflow_execution.py 使用 owner-scoped 过滤(user_id、project_id、source_type)查询 Qdrant 进行 evidence 检索。Rerank collection 支持可配置维度的 late-interaction 模型(默认 96)。

torch

Docling 视觉 PDF 管线所需的深度学习运行时。当 pdf_parser_backend 设为 docling 时,DocumentConverter 加载基于 torch 的视觉模型。在 pypdf 模式下,torch 永不被导入。Worker 以 --pool=solo 运行,避免 Celery fork 与 torch 及 GIL-bound converter 的安全问题。

Outbox 模式

Durable event 分发,消除双写不一致。outbox.py 定义 SqlOutboxStore,使用 FOR UPDATE SKIP LOCKED 批量 claim、CeleryTaskPublisher 的 at-least-once 发布,以及失败时指数退避:min(300, 2^min(attempts, 8))。dispatch_outbox.py 运行专用轮询进程,将 pending events 排入 Celery task 分发。

Lease 并发控制

过期 job lease 防止跨 worker 实例的重复工作。每个 claim() 通过 UPDATE ... RETURNING 原子地设置 lease_owner 和 lease_expires_at。若 worker 崩溃,lease 过期后另一个 worker 重新 claim 该 job。删除操作会阻塞正在运行的 ingestion lease;workflow 分发通过 claim_delivery() 幂等性支持安全重投。

配置与入口

引导 Worker 的四个文件

这些文件负责配置校验、Celery 应用、任务注册(含有界重试)以及在进程边界构造 Provider-backed services 的 builder 函数。

config.py . WorkerSettings

基于 pydantic-settings 的 BaseSettings 类,在任何 managed dependency 构造之前校验所有 worker 配置项。关键分组:运行时限(worker_soft_time_limit_seconds=840、worker_time_limit_seconds=900)、outbox(outbox_batch_size=50、outbox_max_attempts=8)、ingestion lease(ingestion_lease_seconds=1200、ingestion_max_attempts=5)、parser(parser_pipeline_version="resource-aware-v4"、parser_max_pages=300、pdf_parser_backend="pypdf" 或 "docling"、docling_artifacts_path)、workflow(workflow_pipeline_version="evidence-v1"、workflow_lease_seconds=900、workflow_call_budget_reservation_usd=0.25、workflow_max_prompt_tokens=32768、langgraph_strict_msgpack=True)、LLM(nvidia_model="z-ai/glm-5.2"、llm_temperature=1.0、llm_max_tokens=16384、llm_seed=42)、embedding(nvidia_embedding_model="nvidia/nv-embed-v1"、embedding_dimension=4096)、Qdrant(v3 collection、命名 BM25 sparse model、原生 hybrid 灰度开关、rerank collection/model)、web search(tavily)、可观测性(langfuse)、对象存储(R2 或通用 S3,region=auto)。model_validator(mode="after") 强制 preview/production 必须配置 DATABASE_URL、REDIS_URL、对象存储、NVIDIA LLM + embedding、Qdrant、Tavily、Langfuse、strict LangGraph 序列化,且 docling 后端激活时需离线 Docling artifacts。

celery_app.py . create_celery_app()

创建 Celery 应用,broker_url 来自 REDIS_URL(测试用 memory://)。关键设置:task_acks_late=True(执行成功后才 ack)、task_reject_on_worker_lost=True(崩溃时重新入队)、worker_prefetch_multiplier=1(一次只取一个任务)、task_track_started=True、task_ignore_result=True(无 result backend)。task_routes 字典将 6 个任务名路由到 5 个队列:ingest_document 到 ingestion,delete_document 和 delete_project 到 deletion,run_workflow 到 workflow,run_evaluation 到 evaluation,run_fault_simulation 到 reliability。Broker visibility_timeout 设为 worker_time_limit_seconds * 2。三个 Celery 信号(worker_ready、heartbeat_sent、worker_shutdown)通过 record_heartbeat 将有界心跳元数据写入 runtime_heartbeats 表,带可配置节流(runtime_heartbeat_seconds,默认 30)。

tasks.py . 6 个 tasks + 4 个 _mark_* 终态标记函数

注册 6 个 @celery_app.task 装饰器,bind=True,设有界 max_retries。每个任务校验 event payload(Pydantic model_validate),通过 builder 函数构造 service,然后委托执行。可重试失败时,退避公式为 min(300, 2^min(retries+1, 8))。不可重试或 bootstrap 失败时,4 个 _mark_* 终态标记函数之一将 job/run 标记为 failed,以便显式重试恢复:_mark_job_bootstrap_failed(ingestion + deletion jobs,同时标记 documents 为 failed)、_mark_workflow_bootstrap_failed(workflow runs)、_mark_evaluation_run_failed(evaluation runs)、_mark_fault_exercise_failed(fault exercises)。run_workflow 任务最为复杂:获取 delivery lease,构造 PostgresSaver checkpointer(JsonPlusSerializer, pickle_fallback=False),处理三种调用模式(通过 Command 恢复、从 checkpoint 恢复、或全新 initial_state)。

task_builders.py

定义 3 个 task event model(WorkflowTaskEvent、EvaluationTaskEvent、FaultSimulationTaskEvent)和 6 个 builder 函数。build_ingestion_service(lru_cached)构造 DocumentIngestionService,包含 SqlIngestionStore、S3CompatibleObjectStorage、DoclingDocumentParser 和 QdrantHybridStore。build_deletion_service 和 build_project_deletion_service(均 lru_cached)构造删除 service,使用相同适配器栈。build_workflow_domain 构造 SqlEvidenceWorkflowDomain,内含 BudgetedChatProvider 包装 NvidiaChatProvider。build_evaluation_runner 构造 EvaluationRunner,含 QdrantCaseExecutor 和 RagasFaithfulnessScorer。build_fault_simulation_service 仅用数据库引擎构造 FaultSimulationService。每个 builder 在构造适配器前校验必需配置,缺失时抛出 RuntimeError 并附带描述性消息。

文档摄取 . 7 个文件

Ingestion 逐文件详解

摄取管线下载对象、解析文档、投影确定性 chunk 和 page、upsert 向量,然后将 job 转为 ready。每一步均受 lease 保护。

ingestion_models.py
定义数据契约。IngestionEvent(Pydantic BaseModel)校验 job_id、user_id、project_id、document_id。IngestionRecord(frozen dataclass)携带已 claim 的文档元数据。ParsedBlock 携带规范化文本及结构化溯源(page_no、slide_no、section_title、metadata)。PageProjection 携带 page 级文本用于持久化源展示。ParserAdapterError 和 IngestionFailure 以稳定 code 和 retryable 标志归一化失败。4 个 Protocol 类定义适配器边界:DocumentParser、ObjectReader、VectorProjection、IngestionStore。
ingestion_service.py
DocumentIngestionService.handle() 编排完整管线:claim job lease,下载对象到 TemporaryDirectory,校验大小和 SHA-256 checksum,解析为 ParsedBlock 列表,通过 build_projections 投影为 pages + chunks,replace_content 写入 SQL,upsert_chunks 到 Qdrant,mark_ready。失败分类:ObjectStorageRequestError 和 VectorStoreRequestError 可重试;ParserAdapterError 遵循其 retryable 标志;IngestionFailure 直接传递;其他异常变为 INGESTION_INTERNAL_ERROR(不可重试)。_record_failure 方法在可重试且 attempts < max 时选择 mark_retryable,否则 mark_failed。
ingestion_store.py
SqlIngestionStore 实现 IngestionStore protocol 全部方法。claim() 通过 UPDATE ... RETURNING 原子地将 pending 或过期 job 转为 running,设置 lease,并标记 document 为 parsing。查询 join jobs、documents 和 projects 以强制 owner scope、active project 状态和非删除 document。replace_content() 获取 SELECT FOR UPDATE(job + document + project),删除旧 pages 和 chunks,插入新记录(qdrant_point_id = str(chunk.id)),并将 document 转为 indexing。mark_ready() 将 job 转为 succeeded、document 转为 ready。mark_retryable() 和 mark_failed() 以适当状态释放 lease。
ingestion_projections.py + ingestion_chunking.py
build_projections() 将 ParsedBlock 列表转换为(PageProjection 列表, ChunkEntry 列表)。结构感知 chunker 绝不跨越 page、slide 或 section 边界,overlap 复用完整语义单元而不是任意字符,并记录 section title/path/index 与稳定字符偏移。Page 和 chunk ID 由规范化 locator-section 流、pipeline version 和 content hash 确定性派生。再摄取保持幂等,且只在替换向量全部写入成功后清理陈旧点。
parsing.py
DoclingDocumentParser 资源感知。PDF 使用 _parse_pdf_lightweight(pypdf PdfReader,strict=False,页数限制)。若 pdf_backend 为 docling,_pdf_converter 延迟加载 DocumentConverter(PdfPipelineOptions: artifacts_path、enable_remote_services=False)。DOCX 解析通过 _read_bounded_xml 读取 word/document.xml,含流式 zip-bomb 防护(max_xml_bytes)。PPTX 解析通过 regex 发现 slide XML 成员,按 slide 编号排序,提取段落文本。所有 block 携带 metadata:parser_name、parser_version、source_item_ref、source_ordinal、source_label、source_anchors。
parsing_helpers.py
三个纯函数。_normalized_archive_member() 归一化 zip member 路径(反斜杠转正斜杠,去除前导斜杠,casefold)。_package_version() 通过 importlib.metadata 读取包版本,未找到返回 "unknown"。_serialize_provenance() 将 Docling item provenance(item.prov)转换为 anchor 字典,包含 item_ref、locator_kind、page_no、bbox、charspan。无 provenance 时回退到 structural anchor。
jobs.py
chunk_text_for_index(text, target_size=900) 纯函数,将规范化文本切分为有界 chunk。去除空行,拼接段落,累积文本直到超过 target_size,然后开始新 chunk。不丢弃任何内容。由 worker 和 API adapter 共享以复用测试。

Outbox 分发 . 2 个文件

Outbox 逐文件详解

Outbox 模式连接 API 的事务性写入和 Worker 的 Celery task 分发,在保持 at-least-once 语义的同时消除双写不一致。

outbox.py
定义 outbox 基础设施。ClaimedOutboxEvent(frozen dataclass)携带一个已 lease 的 event。OutboxStore Protocol 定义 claim、mark_published、mark_failed、requeue_stale。TaskPublisher Protocol 定义 publish。OutboxDispatcher 编排批量发布:dispatch_once() claim 一个批量(FOR UPDATE SKIP LOCKED,limit=batch_size),发布每个 event,并标记结果。recover_stale_claims() 将卡在 publishing 状态超过 15 分钟的 event 重新入队。SqlOutboxStore 以原子 SQL 实现全部状态转换。CeleryTaskPublisher 通过 TASK_BY_EVENT 将 7 种 event type 映射到 6 个 Celery task name,路由到正确队列(deletion、workflow、evaluation、reliability 或默认 ingestion)。mark_failed 延迟使用 min(300, 2^min(attempts, 8))。
dispatch_outbox.py
专用 dispatcher 进程的入口点。build_dispatcher() 从 WorkerSettings 构造 OutboxDispatcher,内含 SqlOutboxStore 和 CeleryTaskPublisher。main() 解析 --once 和 --poll-seconds 参数,启动时调用 recover_stale_claims(),然后循环:记录 dispatcher 心跳,调用 dispatch_once(),若无 event 发布则休眠。此进程是 render_combined.py 监管的 3 个子进程之一。
At-least-once 分发: API 在与领域变更同一事务中写入 outbox_events。Dispatcher 使用 FOR UPDATE SKIP LOCKED claim event,以 event 的 idempotency_key 作为 task_id 发布为 Celery task,然后标记为 published。若 worker 在发布后、标记前崩溃,event 被重新入队并重投。每个 service 中的幂等 claim() 和 lease 逻辑使重投安全。

LangGraph 工作流 . 9 个文件

LangGraph 逐文件详解

Evidence 工作流是一个 6 节点 LangGraph StateGraph:规划研究问题、检索并提取 claim、reconcile 关系、可选暂停等待人工审查、合成报告,然后原子提交到 8 张数据库表。

evidence_graph.py
定义 EvidenceWorkflowState(TypedDict,total=False),含 24 个字段携带 checkpoint-safe 状态。EvidenceWorkflowDomain Protocol 定义 7 个应用决策方法。build_evidence_graph() 延迟构建 StateGraph(延迟导入 langgraph)。图含 6 个节点:plan、retrieve_and_extract、reconcile、human_review、synthesize、validate_and_commit。plan 使用 conditional_edges 和 fan_out 函数,为每个 question 创建一个 Send,实现并行检索。human_review 包裹 interrupt() 而不用 try/except,使 LangGraph 能持久化并呈现中断。边:START 到 plan,plan fan-out 到 retrieve_and_extract,retrieve_and_extract 到 reconcile,reconcile 到 human_review,human_review 到 synthesize,synthesize 到 validate_and_commit,validate_and_commit 到 END。
workflow_core.py
SqlEvidenceWorkflowDomain 继承 WorkflowExecutionMixin、WorkflowCommitMixin、WorkflowEventsMixin。持有 engine、provider、vector_store、pipeline_version 和可选 web_search。bind_run() 将 run context 附加到 BudgetedChatProvider。initial_state() 校验 ownership 和 pipeline 配置(WorkflowPipelineConfig),处理 report_refresh 类型(校验 base report 和 impacted sections),并构造初始 EvidenceWorkflowState。claim_delivery() 获取过期 delivery lease(支持 pending、running、waiting_human 状态)。release_delivery() 仅释放当前 worker 的 lease。record_retry() 将重试意图记录为 run_event,不标记 run 为终态。
workflow_execution.py
WorkflowExecutionMixin 提供 Provider-facing 决策。plan() 通过 build_research_plan 创建研究问题,或为 refresh 保留确切 section key。retrieve_and_extract() 以 owner-scoped 过滤查询 Qdrant,可选扩展 web search(Tavily),去重 chunk,通过 extract_claims 提取 claim。reconcile() 通过 reconcile_claims 派生 claim 关系。review_payload() 仅在 confidence < 0.75 或检测到不可信源(web page、prompt-injection 标记)时请求人工审查。apply_decision() 应用 approve/edit/reject 决策。synthesize() 通过 synthesize_report 构建 ReportProposal。validate_and_commit() 在调用 _commit 前拒绝无 evidence 的 claim。resume_value() 加载一个已持久化的人工决策。mark_failed() 使 workflow 失败成为终态并释放 lease。
workflow_commit.py
WorkflowCommitMixin(继承 WorkflowEvidenceLoaderMixin)在单个事务内持久化一个 workflow 结果。_commit() 写入 8 张表:ask_runs(将 workflow 关联到 ask run)、research_questions、citations、claims(含递增 source_version)、claim_evidence、claim_relations、reports(含 revision 编号)、report_sections。对于 report_refresh,校验生成的 section 精确匹配 impacted section,仅替换这些 section,保留未变更 section,并使 base report 失效。pg_advisory_xact_lock on project 串行化提交,确保 claim version 和 report revision 唯一。
workflow_events.py
WorkflowEventsMixin 提供结构化 event 写入。_node_started() 记录 node_started event(含 progress)。_node_completed() 记录 node_completed event(含 progress 和 payload)。_event() 是共享的 static method,获取 pg_advisory_xact_lock(hashtextextended(run_id))并通过 coalesce(max(sequence)+1)插入自增 sequence 的 run_event。
workflow_loader.py
WorkflowEvidenceLoaderMixin 提供 _load_chunks(),通过 owner- 和 project-scoped SQL 查询解析 workflow state 引用的 evidence。按 user_id、project_id 和 chunk_id 列表查询 chunk,保持原始顺序并过滤缺失 ID。这确保 workflow 在加载 evidence 时不扩大其 ownership scope。
workflow_models.py
定义 WorkflowRuntimeError(RuntimeError,含 code 和 retryable 属性)。WorkflowPipelineConfig(Pydantic BaseModel)校验 retrieval_limit(1-50)、model 和 evidence_prompt_version(pattern: evidence-review-v[0-9]+)。_json() 是紧凑 JSON 序列化器,ensure_ascii=False,default=str。
workflow_runtime.py
SqlEvidenceWorkflowDomain 子类,保留历史导入路径和 workflow 编排客户端的 monkeypatch seam。覆写 synthesize() 以维护测试使用的公共合成 seam。重新导出 build_research_plan、extract_claims、reconcile_claims、synthesize_report(来自 researchmate_api.services.evidence_generation)。
budget.py
BudgetedChatProvider 包装 ChatProvider delegate,增加每次调用的 USD 预留和 prompt token 限制。bind_run() 附加 run_id。complete() 估算 prompt token(len/4+1),超过 max_prompt_tokens 时拒绝(WorkflowBudgetExceeded),原子地预留 budget_reserved_usd(不超过 budget_limit_usd),调用 delegate,并将实际成本 + 延迟 + token 使用量记录到 run_events。_reserve() 使用 UPDATE ... WHERE budget_reserved_usd + amount <= budget_limit_usd RETURNING 原子校验并预留。
8 表原子提交: _commit 在单个事务中写入 ask_runs、research_questions、citations、claims、claim_evidence、claim_relations、reports 和 report_sections。这确保 workflow 结果要么完整持久化,要么完整回滚,不会产生部分报告或孤立 claim。

删除 . 3 个文件

Deletion 逐文件详解

删除在标记 durable job 完成之前移除远程 artifact(Qdrant point、S3 object)。文档删除和项目删除按 aggregate 拆分,但共享相同的 lease 和重试语义。

deletion_models.py
定义数据契约。DocumentDeletionEvent 和 ProjectDeletionEvent(Pydantic)校验 job_id、user_id、project_id(文档删除另含 document_id)。DeletionRecord 和 ProjectDeletionRecord(frozen dataclass)携带已 claim 的 artifact。4 个 Protocol 类:DeletionStore(claim、mark_ready、mark_retryable、mark_failed)、ObjectDeletion(delete)、VectorDeletion(delete_points、delete_project_points)、ProjectDeletionStore。
deletion_document.py
SqlDeletionStore.claim() 首先失败同一文档的任何正在运行的 ingestion job(DOCUMENT_DELETING),然后通过 UPDATE ... RETURNING 原子 claim 删除 job,带有 NOT EXISTS 守卫防止活跃 ingestion lease。若被阻塞,抛出 IngestionFailure("DOCUMENT_INGESTION_RUNNING", retryable=True)。mark_ready() 获取 SELECT FOR UPDATE,删除 document_pages 和 chunks,将 deletion_jobs 和 jobs 转为 succeeded。DocumentDeletionService.handle() claim、删除 Qdrant point、删除 S3 object、标记 ready。失败分类为 OBJECT_DELETE_UNAVAILABLE、VECTOR_DELETE_UNAVAILABLE 或 DELETE_INTERNAL_ERROR。
deletion_project.py
SqlProjectDeletionStore.claim() 失败项目的所有 pending/running ingestion job,然后 claim 项目删除 job。RETURNING 子句通过子查询聚合项目的所有 r2_object_key 和 qdrant_point_id。mark_ready() 置空 job 外键,硬删除 project 行,转换 jobs。ProjectDeletionService.handle() claim、删除所有 Qdrant project point、删除每个 S3 object key、标记 ready。重试/失败分类与文档删除相同。

评估 . 7 个文件

Evaluation 逐文件详解

评估系统对 frozen dataset 运行 lease 保护的回归测试,使用确定性指标和可选 RAGAS faithfulness judge 对 grounded answer 评分。

evaluation_models.py
定义不可变数据契约。PipelineRuntimeConfig(Pydantic)校验 retrieval_limit、model、evaluation_prompt_version(pattern: grounded-answer-v[0-9]+)、retrieval_mode。EvaluationCase(frozen dataclass)携带一个 dataset case,含 input、expected_output、expected_evidence。PipelineResult 携带生成的 answer、contexts、retrieved 和 cited chunk ID。MetricScore 携带一个指标结果,含 name、version、value、passed、details、judge_model。ClaimedEvaluation 携带 lease 保护的 run policy。EvaluationRuntimeError 含 code + retryable。两个 Protocol:CaseExecutor、FaithfulnessScorer。SUPPORTED_METRICS = {schema_valid, citation_precision, evidence_recall, faithfulness}。
evaluation_executor.py
QdrantCaseExecutor.execute() 先应用生产检索规划器,再查询 owner-scoped Qdrant chunk(LOCAL_DOC source type),因此评估会覆盖精确、语义与平衡 hybrid 权重,不再是硬编码向量查询。随后校验 provider model 与 prompt version,调用 build_llm_grounded_answer,返回 response、contexts、retrieved_chunk_ids 与 cited_chunk_ids。
evaluation_persistence.py
EvaluationPersistenceMixin 提供 lease 安全的数据库操作。_claim() lease 一个 pending 或过期的 evaluation run,校验 accepted pipeline version,从 summary 加载 metrics,强制 metric 为 SUPPORTED_METRICS 子集,构造 ClaimedEvaluation(bounded max_parallelism 1-20,默认 4)。_load_cases() 加载 join 到 run dataset 的 frozen case。_completed_case_ids() 识别所有请求指标已持久化的 case。_reserve_case_budget() 原子预留 per-case USD,不超过上限。_save_scores() 持久化 score(含 lease 验证和 ON CONFLICT DO UPDATE)。_complete() 构建回归摘要,将当前指标与最近成功的 baseline run 比较。
evaluation_runner.py
EvaluationRunner(继承 EvaluationPersistenceMixin)协调有界并行评估。run() claim lease,加载 case,过滤已完成 case,然后使用 ThreadPoolExecutor(max_workers=claimed.max_parallelism)并行执行 pending case。每个 case 预留 budget,通过 CaseExecutor 执行,用 deterministic_scores + 可选 faithfulness 评分,保存 score。可重试失败被收集;若 attempts < max_attempts,run 被释放以重试。否则,永久失败被计数,_complete() 以回归摘要完成 run。
evaluation_scoring.py
deterministic_scores() 计算 3 个可复现指标,无需 LLM:schema_valid(响应非空 + 有 citation)、citation_precision(cited AND retrieved / cited)、evidence_recall(expected AND retrieved / expected,通过阈值 0.8)。RagasFaithfulnessScorer 使用 Ragas 0.4 collections API(Faithfulness 指标),后端为 NVIDIA AsyncOpenAI client,在 asyncio.run() 中运行。通过阈值 0.8。若 ragas 不可导入则抛出 RAGAS_NOT_INSTALLED。
evaluation_summary.py
build_regression_summary() 将当前指标聚合与 baseline run 比较,计算每个指标的 mean_delta 和 pass_rate_delta。当 mean_delta < -0.02 或 pass_rate_delta < -0.05 时检测到回归。摘要包含 completed_cases、failed_cases、execution_succeeded、quality_passed、metric_summary、baseline_comparison、regressed_metrics 和 budget 追踪。_metric_aggregates() 按 metric_name 分组查询 evaluation_scores。_safe_evaluation_error() 按 code 和 retryable 属性分类异常,默认不可重试而非字符串匹配类名。json_dumps() 是用于 SQL 写入的紧凑序列化器。
evaluation.py
稳定 facade。重新导出 evaluation_executor、evaluation_models、evaluation_runner、evaluation_scoring 和 evaluation_summary 的全部公共符号。为 task_builders.py 提供单一导入面。

可靠性 . 1 个文件

Fault simulation

fault_simulation.py 记录有界的失败/恢复演练,不修改任何 provider、workflow run 或外部服务。

fault_simulation.py . FaultSimulationService

非修改型可靠性验证器。SCENARIO_BOUNDARIES 将 4 个场景映射到边界名:llm_timeout(chat_provider_timeout_boundary)、qdrant_unavailable(vector_projection_unavailable_boundary)、worker_interrupt(lease_recovery_boundary)、r2_failure(object_storage_failure_boundary)。run() 通过 UPDATE ... RETURNING(含 lease 和 attempt 守卫)claim 一个演练,查找边界,快照可选的 target workflow run,并持久化 safe_result(simulation_only=True、external_calls=0、injected_boundary、simulated_transition、recovery_state、target_snapshot)。不支持的场景以 FAULT_SCENARIO_UNSUPPORTED 失败。整个 claim-snapshot-complete 周期是一个短事务,数据库失败时回滚,task 保持安全可重放。

进程监管 . 2 个文件

组合部署与运行时健康

render_combined.py 监管 3 个子进程;runtime_health.py 持久化公共 readiness probe 消费的非密 liveness 信号。

render_combined.py

单容器组合部署的进程监管器。child_commands() 声明 3 个监管命令:(1) uvicorn 服务 researchmate_api.main:app,配置端口和 proxy headers;(2) celery worker,-A researchmate_worker.celery_app:celery_app,--queues=ingestion,deletion,workflow,evaluation,reliability,--pool=solo,--concurrency=1;(3) python -m researchmate_worker.dispatch_outbox。apply_schema_migrations() 可选地在任何进程启动前运行迁移(RUN_SCHEMA_MIGRATIONS=1)。backfill_qdrant_rerank() 可选地 provision rerank collection(RUN_QDRANT_RERANK_BACKFILL=1)。wait_for_api() 轮询 /api/v1/healthz 直到 200 才启动 worker(超时 240 秒)。信号处理器将 SIGTERM 和 SIGINT 转发给所有子进程。监管器每 0.5 秒轮询子进程退出码并传播失败。

runtime_health.py

record_heartbeat() 将非密 liveness 信号 upsert 到 runtime_heartbeats 表。INSERT ... ON CONFLICT (component) DO UPDATE 写入 component、instance_id(默认 socket.gethostname())、status、safe_metadata(JSON)和 updated_at。由 celery_app.py 的信号处理器(worker ready/heartbeat/shutdown)和 dispatch_outbox.py 的每次轮询周期调用。metadata payload 有界且非密(如 {"queues": "ingestion,deletion,workflow,evaluation,reliability"} 或 {"poll_seconds": 2.0})。

文档摄取切片

Document ingestion . 7 步 proof chain

从 outbox event 到达 Celery task 到 document 转为 ready,分发经过的每个函数:

1. Event 校验tasks.py:IngestionEvent.model_validate(event) 校验 job_id、user_id、project_id、document_id
2. Lease claimingestion_store.py:SqlIngestionStore.claim() 通过 UPDATE ... RETURNING 原子地将 job 转为 running,设置 lease_owner + lease_expires_at,标记 document 为 parsing
3. 对象下载ingestion_service.py:S3CompatibleObjectStorage.download_to_file() 写入 TemporaryDirectory;校验大小不超过 max_upload_bytes
4. Checksum 校验ingestion_service.py:下载字节的 SHA-256 与 record.checksum_sha256 比较;不匹配抛出 CHECKSUM_MISMATCH(不可重试)
5. 解析parsing.py 路由 42 种文件类型：轻量 PDF、有界 DOCX/PPTX/XLSX OOXML、HTML 可见文本、Notebook 输入单元和解码后的文本块。所有路径都返回带出处信息的 list[ParsedBlock]。
6. 投影ingestion_projections.py:build_projections() 从 content_hash 派生确定性 UUID5 page + chunk ID;jobs.py chunk_text_for_index 切分文本
7. 轻量或向量索引ingestion_service.py:is_lightweight_corpus() 累加 chunk token 数;不超过 lightweight_token_threshold(4000)时跳过 Qdrant upsert(has_vector=False),否则 QdrantHybridStore.upsert_chunks()(has_vector=True)
8. Wiki 编译(仅轻量文档)轻量文档经 WikiCompiler.compile() 通过 LLM 编译为结构化 wiki 页面(标题、[[wikilinks]]、来源引用);转换回 ChunkEntry 并标记 wiki_mode 元数据。LLM 失败时回退到原始 chunk。
9. 持久化 + readyingestion_store.py:replace_content() 写入 pages + chunks(SELECT FOR UPDATE),mark_ready() 将 job 转为 succeeded + document 转为 ready
重试退避: 可重试失败时,task 以 countdown = min(300, 2^min(retries+1, 8)) 重新抛出。指数项上限为 2^8=256,整体延迟上限为 300 秒。不可重试失败调用 _mark_job_bootstrap_failed 或 mark_failed 使 job 成为终态。

Evidence workflow . 6 节点 proof chain

从 workflow task claim delivery lease 到 8 表原子提交,图执行的每个节点:

1. planworkflow_execution.py:通过 LLM 调用 build_research_plan();report_refresh 时保留确切 impacted section key。输出 questions 列表。Progress:5 到 15。

Checkpoint 恢复: run_workflow task 处理三种模式:(1)提交人工决策时通过 Command(decision_id)恢复,(2)get_tuple 返回非 None 时从已有 checkpoint 恢复,(3)通过 initial_state() 全新启动。PostgresSaver 配合 JsonPlusSerializer(pickle_fallback=False)确保严格、可移植的 checkpoint。

Outbox 分发切片

Outbox dispatch . proof chain

从 dispatcher 轮询 outbox 表到 Celery task 被分发,at-least-once 管线的每一步:

1. 恢复 staledispatch_outbox.py:recover_stale_claims() 将卡在 publishing 状态超过 15 分钟的 event 重新入队为 failed
2. Claim 批量outbox.py:SqlOutboxStore.claim() 选择 pending/failed 且 available_at <= now、attempts < max_attempts 的 event,使用 FOR UPDATE SKIP LOCKED,limit=batch_size
3. 发布outbox.py:CeleryTaskPublisher.publish() 通过 TASK_BY_EVENT 将 event_type 映射到 task_name,路由到正确队列,调用 celery_app.send_task(),以 idempotency_key 作为 task_id
4. 标记已发布outbox.py:SqlOutboxStore.mark_published() 仅在 status 为 publishing 时将状态转为 published,published_at=now()
5. 标记失败outbox.py:发布异常时,mark_failed() 设置 status=failed,safe_error(截断 200 字符),available_at = now() + min(300, 2^min(attempts, 8)) 秒
7 种 event type 到 6 个 task name: document.ingest.requested、document.delete.requested、project.delete.requested、workflow.run.requested、workflow.resume.requested(均映射到 run_workflow)、evaluation.run.requested、fault.exercise.requested。队列路由:deletion event 到 deletion 队列,workflow event 到 workflow 队列,evaluation event 到 evaluation 队列,fault event 到 reliability 队列,ingestion event 到配置的 ingestion 队列。
