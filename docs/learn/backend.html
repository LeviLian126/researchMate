Backend . apps/api

The ResearchMate backend is a FastAPI application exposing 45 REST operations under /api/v1 and 6 MCP tools over Streamable HTTP. It owns authentication, grounded-query orchestration, provider adapters, idempotency, and a dual in-memory / PostgreSQL persistence layer. This page walks through every source file in apps/api/src/researchmate_api/.

Technology stack fundamentals

12 dependencies that power the backend

Each card explains what the library does in general and how ResearchMate uses it specifically.

FastAPI

Web framework that assembles the REST API. main.py creates the app with lifespan, CORS middleware, a custom request-id middleware, typed error responses via response_model, and automatic OpenAPI schema. All 11 routers are mounted under /api/v1.

Pydantic

Data validation for every request and response. BaseModel subclasses enforce Field constraints (min_length, max_length, ge, le), ConfigDict(extra="forbid") on inputs, model_validator for cross-field rules, and use_enum_values for stable JSON serialization.

SQLAlchemy

SQL toolkit managing the PostgreSQL engine. create_engine with pool_pre_ping and pool_recycle=300 keeps connections healthy. Raw SQL executes via text() within context-managed transactions that inject the RLS parameter request.jwt.claim.sub.

psycopg

PostgreSQL adapter. The _psycopg_url helper normalizes postgres:// and postgresql:// to postgresql+psycopg:// so SQLAlchemy uses the synchronous psycopg driver. All database operations are synchronous, offloaded to anyio.to_thread when needed.

PyJWT

JWT verification for Supabase authentication. PyJWKClient caches JWKS signing keys. decode validates RS256 or ES256 with audience and issuer checks. Required claims: exp, iat, sub, aud, iss. Role is derived from app_metadata.role, defaulting to user.

Qdrant

Vector database for hybrid retrieval. QdrantClient fuses dense and sparse vectors via RRF, enforces owner-scoped payload filters (user_id, project_id, source_type), and supports late-interaction reranking through Document models in a dedicated rerank collection.

OpenTelemetry

Distributed tracing. OTLPSpanExporter sends spans to a collector endpoint. FastAPIInstrumentor instruments the app automatically. Resource tags service.name and deployment.environment.name. The tracer provider is owned by ObservabilityRuntime and shut down cleanly on exit.

Langfuse

LLM observability. provider_observation wraps every NVIDIA chat and embedding call with a generation or embedding observation, recording model, input metadata, and usage details. Falls back to _NoopObservation when LANGFUSE_ENABLED is false.

OpenAI SDK

Client for NVIDIA NIM endpoints. OpenAI(base_url=nvidia_base_url, api_key, timeout, max_retries=0) is used for chat.completions.create and embeddings.create. The SDK is wrapped by NvidiaChatProvider and NvidiaEmbeddingProvider, never called directly by services.

boto3

S3-compatible object storage client. S3CompatibleObjectStorage wraps boto3.client("s3") to presign upload URLs and read object metadata via head. Supports Cloudflare R2 (account-scoped endpoint) or any generic S3 endpoint.

httpx

HTTP transport used by the OpenAI SDK and Tavily web search provider. Provides synchronous HTTP with configurable timeouts. The Tavily adapter posts search queries to api.tavily.com and normalizes results into ChunkEntry objects.

MCP

Model Context Protocol server. FastMCP exposes 6 tools (list_projects, search_project, search_conversation, ask_grounded, get_run_trace, run_evaluation) and 3 resources (project documents, conversation documents, run summary) over Streamable HTTP, authenticated by the same bearer middleware as REST.

Core files

The five files that bootstrap the API

These files own application assembly, configuration validation, authentication, the MCP surface, and observability lifecycle.

main.py . create_app()

The application factory. It constructs the FastAPI instance with a lifespan that owns the MCP session manager and observability shutdown. Adapters are resolved from Settings and stored on app.state: store (ResearchMateRepository), evidence_store (EvidenceRepository), chat_provider (NvidiaChatProvider or None), hybrid_store (QdrantHybridStore or None), reranker (RerankCoordinator), and web_search (TavilyWebSearchProvider or None). A custom HTTP middleware attaches X-Request-ID and security headers (Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, X-Frame-Options: DENY) to every response, authenticates MCP requests at /mcp, and logs a structured http_request_completed event with latency. Two exception handlers map HTTPException and RequestValidationError into the stable ErrorResponse envelope. The 11 routers are included under /api/v1 with tags. If the MCP SDK is installed, its ASGI app is mounted at /mcp; otherwise a 503 stub returns MCP_RUNTIME_NOT_INSTALLED.

config.py . Settings

A pydantic-settings BaseSettings class validating every runtime knob. Key groups: environment (app_env: local/test/preview/production), auth (auth_mode: development/supabase), repository (memory/postgres), LLM (nvidia model, temperature, top_p, max_tokens, seed, timeout), embedding (4096-dim NVIDIA nv-embed-v1), Qdrant (collection, rerank collection, rerank model), rerank (auto/qdrant/nvidia/deterministic with candidate_limit=50, top_n=10), token budgets (chat_history=5000, recent=3500, summary=1500, full_context=12000, retrieval_evidence=8000), web search (tavily), CORS, observability (OTEL + Langfuse), and object storage (R2 or generic S3). A model_validator(mode="after") rejects unsafe combinations: preview/production must use Supabase auth, PostgreSQL, Redis, object storage, NVIDIA LLM + embedding, Qdrant, Tavily, and Langfuse. get_settings() is lru_cached.

dependencies.py

FastAPI dependency providers and authentication logic. get_store, get_chat_provider, get_hybrid_store, get_web_search, get_reranker, and get_evidence_store read singletons from request.app.state. get_current_user resolves a bearer token via resolve_bearer_token, which dispatches to _development_user (fixed dev tokens or dev:user_id:role:email format) or _supabase_user (JWKS-verified JWT with RS256/ES256). After resolving the user, repository.ensure_user persists the canonical profile. require_admin gates developer/admin-only routes. Error helpers (error_detail, raise_api_error, not_implemented_detail) build the stable error envelope consumed by the global exception handler.

mcp_server.py . build_mcp_server()

Builds a stateless FastMCP server exposing 6 tools and 3 resources. Tools: list_projects, search_project, search_conversation, ask_grounded (full GroundedQueryService execution with IdempotencyCoordinator), get_run_trace (admin-gated), run_evaluation (admin-gated). Resources: project://{project_id}/documents, conversation://{conversation_id}/documents, run://{run_id}. Each request is authenticated by main.py middleware, which sets a ContextVar MCPRequestIdentity carrying the user, repository, evidence store, providers, and settings. The _identity() helper fails closed with PermissionError if no identity is set. The server uses stateless_http=True and json_response=True.

observability.py

Configures privacy-safe logging and optional telemetry. log_event emits bounded JSON events (never prompts, tokens, or document text) via the researchmate logger. configure_observability optionally starts OpenTelemetry (OTLPSpanExporter + BatchSpanProcessor + FastAPIInstrumentor) and Langfuse (get_client). ObservabilityRuntime owns the tracer provider and Langfuse client, flushing and shutting them down on lifespan exit. provider_observation is a context manager that wraps provider calls with a Langfuse generation/embedding observation, or yields _NoopObservation when tracing is disabled or the exporter is unavailable.

routers/ . 11 files

Router file-by-file breakdown

Each router is a thin HTTP adapter that authenticates, delegates to a service, and maps errors into the stable API envelope.

ask.py
POST /ask. The unified Ask endpoint. Accepts AskRequest with an optional Idempotency-Key header (8-160 chars). Constructs an IdempotencyCoordinator, calls begin() to check for replay, executes GroundedQueryService.execute(), and calls complete() or abandon(). Maps IdempotencyError to 409 and GroundedQueryError to its status code.
conversations.py
8 endpoints. List all conversations, create/list conversations in a project, list messages (bounded to 200), rename, delete with attachment cleanup (atomic), and two admin-only rerank-config routes (GET + PUT with optimistic version check). The PUT verifies Qdrant rerank readiness before activation.
dev_traces.py
GET /dev/traces/{trace_id}. Admin-only endpoint returning a redacted DeveloperTrace through TraceQueryService, which enforces the developer/admin role policy shared with MCP.
documents.py
7 endpoints. Upload-url reservation (signed PUT), create document metadata, list project/conversation documents, get single document, complete upload (verifies object metadata, enqueues ingestion job, accepts local-only extracted_text), and delete document (enqueues deletion job). Maps UploadVerificationError to 409 and ObjectStorage errors to 503.
evidence.py
Evidence workflow endpoints. Creates idempotent research runs (202), reads workflow runs, streams run events via SSE, lists/gets reports, lists pipeline versions, lists evaluation datasets (admin), creates evaluation runs (admin), refreshes reports (202), reads reliability aggregates (admin), and creates/reads fault scenarios (admin, non-production only). All async writes require an 8-160 char Idempotency-Key.
health.py
GET /healthz + GET /readyz. healthz returns ok without touching dependencies. readyz probes database (select 1 + checkpoint tables + heartbeats + outbox backlog), Redis (ping), Qdrant (get_collection), object storage, LLM, and web search. Returns 503 with failed_components list when any required dependency is unavailable.
jobs.py
GET /jobs/{job_id}. Returns a JobRecord visible only to the authenticated caller who owns it.
me.py
GET /me. Returns the CurrentUser established by get_current_user. The simplest router: one dependency, one response.
projects.py
5 endpoints. POST /chat/bootstrap returns the hidden personal project. POST /projects creates a workspace project. GET /projects lists owned workspaces. GET /projects/{id} returns one project. DELETE /projects/{id} enqueues cleanup (202).
quiz.py
POST /quiz + GET /projects/{id}/quiz. POST generates a source-backed Quiz through QuizService with IdempotencyCoordinator. GET lists saved QuizSets for a project. Maps QuizServiceError to its status code (404, 409, 429, 503).
runs.py
GET /runs/{run_id}/sources. Returns the Sources panel data (RunSourcesResponse with citation summary and validated citations) for a caller-visible run.

services/ . Orchestration group (15 files)

Application orchestration services

These services coordinate business logic without owning adapter mechanics. They depend on the ResearchMateRepository protocol and provider Protocols, never on concrete adapter classes.

grounded_query.py
GroundedQueryService. The unified Ask orchestrator. execute() runs the full pipeline: prepare conversation scope, retrieve local evidence (BM25 + Qdrant), optionally retrieve web evidence, rerank candidates, generate answer (grounded or chat), increment usage quota, and record the run with trace. Builds ToolCallTrace entries for each stage and packs runtime_metadata (context_strategy, rerank provider/model, token estimates, latency) into the persisted trace.
answering.py
Answer builder with three modes. build_llm_grounded_answer: constructs evidence JSON with server-assigned evidence_id integers, validates provider output against GroundedAnswerProposal schema, allows one schema repair, maps evidence_ids to Citation objects. build_grounded_answer: deterministic local answer from chunks. build_llm_chat_answer / build_chat_answer: plain chat without evidence. _extract_json_object handles markdown-fenced LLM output.
query_context.py
ConversationContextBuilder. Loads conversation history, applies token budgets (recent=3500, summary=1500, trigger=8000), compresses old messages into LLM-generated summaries, and wraps cross-conversation project memory as untrusted data inside an XML-like block. bound_messages keeps newest messages within a hard token budget. _truncate_to_budget trims oversized messages.
query_conversation.py
QueryConversationCoordinator. prepare() validates the project is active, resolves an existing conversation, loads documents and chunks (workspace vs personal scope), rejects documents still in PARSING/INDEXING status, and builds conversation context. ensure_for_commit() creates the conversation only after generation succeeds, avoiding empty conversations on failure.
query_errors.py
GroundedQueryError exception carrying code, message, and status_code. raise_grounded_error helper. Shared by all query_* modules to propagate stable errors without coupling to HTTP.
query_execution.py
Web retrieval and execution-plan helpers. retrieve_web calls TavilyWebSearchProvider or raises WebEvidenceError. limit_rerank_candidates diversifies by document while reserving slots for web results. build_execution_plan maps the strategy (full_context / hybrid_retrieval / web / hybrid_retrieval_web / chat) to an ExecutionPlan.
query_generation.py
generate_answer dispatcher. With retrieved evidence: grounded LLM or deterministic. With documents but no evidence and no web: abstains with an honest message. Without documents: plain chat. Maps ProviderOutputError to 502 and ProviderRequestError to 503. Returns GenerationOutcome with answer, citations, summary, LLMResult, and latency.
query_retrieval.py + query_planning.py
LocalEvidenceRetriever now routes the complete authorized corpus through five observable policies: full context, exact lexical-heavy, semantic dense-heavy, balanced hybrid, and expanded hybrid. Follow-up or compound ambiguity permits one schema-validated rewrite call with at most three total variants; the original query is always retained. Native mode sends named BM25 and dense branches to Qdrant with route weights divided fairly across variants. Planner or vector failure is recorded and degrades to bounded application BM25.
idempotency.py
IdempotencyCoordinator. Four-state machine: begin() returns execute (new key), replay (cached response), mismatch (different body, same key), or in_progress (concurrent). complete() persists the response snapshot. abandon() releases the pending reservation on failure. request_hash canonicalizes the Pydantic payload via sorted JSON + SHA-256.
access_policy.py
TraceQueryService. Centralizes the developer/admin trace-access policy. get() returns a DeveloperTrace only to developer or admin roles, raising TraceAccessError otherwise. Shared by the HTTP dev_traces router and the MCP get_run_trace tool.
scope_policy.py
require_workspace_scope guard. Raises ProjectScopeError if a project is not kind=workspace. Used by MCP search_project and project_documents resource to prevent personal-project access through MCP.
evidence_faults.py
Fault scenario service for non-production reliability exercises. Supports four scenarios: llm_timeout, qdrant_unavailable, worker_interrupt, r2_failure. Bounded duration (1-60 seconds). Only available in local/test/preview environments.
evidence_generation.py
Evidence report generation. Creates draft reports from research run outputs, generates report sections with evidence snapshots, and handles incremental refresh when source documents change. Tracks validation_status per section.
evidence_store.py
EvidenceRepository Protocol defining the evidence-workflow persistence boundary: create/get research runs, append events, list claims and relations, list/get reports, list pipeline versions, create evaluation runs, reliability aggregates, fault scenarios. InMemoryEvidenceRepository provides a process-local implementation. EvidenceStoreError carries code, message, status_code.
quiz_generation.py
Quiz set generation. generate_llm_quiz_set: constructs evidence JSON, validates provider output against QuizSetProposal schema (exactly 4 options for single_choice, evidence_ids within allowlist). generate_quiz_set: deterministic local quiz with Chinese-language questions sourced from chunk snippets. QuizGenerationError for invalid provider output.
Also: quiz_service.py orchestrates Quiz retrieval, generation, coverage measurement, usage quota, trace, and persistence. It validates project scope (workspace only), selects chunks (all_ready_documents or topic), generates via LLM or deterministic fallback, records the quiz run, and returns QuizResponse with honest QuizCoverage.

services/ . Provider adapter group (7 files)

Provider adapters and retrieval utilities

Each adapter wraps an external SDK behind a Protocol interface, normalizing errors and telemetry. Services depend on Protocols, never on concrete classes.

llm.py
ChatProvider Protocol (complete, complete_bounded, stream). NvidiaChatProvider wraps OpenAI(base_url=nvidia_base_url) with temperature, top_p, max_tokens, seed, and max_retries=0. _request wraps every call in provider_observation (Langfuse). Maps provider exceptions to ProviderRequestError(retryable) based on status codes (408/409/429/500/502/503/504). LLMResult normalizes content, reasoning_content, model, and token usage.
embedding.py
NvidiaEmbeddingProvider. Wraps OpenAI embeddings.create with extra_body={input_type, truncate:END}. Validates vector count and dimension (4096) against settings. Provider errors normalized to ProviderRequestError. Observation wraps input_count, input_chars, and usage.
qdrant_store.py + qdrant_hybrid_query.py
QdrantHybridStore repeats owner, project, source, and optional document filters on every prefetch branch and final query. The v3 shadow collection has named 4096-dimensional dense vectors plus named bm25 sparse vectors with IDF, populated through qdrant/bm25 Document inference. Weighted RRF reflects the selected route. Re-ingestion snapshots document point IDs, writes all replacements, then removes stale primary and rerank points. A configuration flag preserves the legacy application-BM25 + dense rollback path during rollout.
rerank.py
RerankCoordinator. Three-way fallback: Qdrant native (late-interaction Document rerank), NVIDIA ranking API, and Deterministic (lexical score + RRF). Selects provider based on runtime config (get_runtime_rerank_config) or settings default. Returns RerankResult with provider, model, candidates, degraded flag, and fallback_reason. Caches rerank-config reads for 5 seconds.
web_search.py
TavilyWebSearchProvider. Posts search queries to api.tavily.com, normalizes results into ChunkEntry objects with SourceType.WEB_PAGE. WebSearchRequestError carries retryable flag. Timeout configurable via web_search_timeout_seconds (default 30s). Results include url, title, and content snippet.
object_storage.py
S3CompatibleObjectStorage. Wraps boto3.client("s3") with presign_upload (signed PUT URL, 600s expiry) and head (reads size_bytes, content_type, etag). ObjectStorageConfigurationError when not fully configured. UploadVerificationError for size/type mismatch. StoredObjectMetadata dataclass normalizes head response. Supports R2 (account-scoped endpoint) or generic S3.
retrieval.py
Deterministic lexical retrieval utilities shared by in-memory and Qdrant paths. tokenize() extracts Latin words, CJK characters, and CJK bigrams. bm25_candidates() scores chunks with BM25 (k1=2.2, b=0.75) plus exact-match and title-match boosts. fuse_candidates() applies Reciprocal Rank Fusion (RRF k=60). pack_chunks() packs whole chunks within a token budget. estimate_tokens() provides a conservative mixed-text token estimate. snippet() collapses whitespace for display.

services/ . Store group (12 files)

In-memory store: protocol, models, core, text utils, and mixins

The store group assembles InMemoryResearchMateStore from aggregate-focused mixins. The same ResearchMateRepository Protocol is implemented by both the in-memory store and PostgresResearchMateRepository, enabling zero-code swap via REPOSITORY_BACKEND.

Request slice

POST /api/v1/ask . 10-step proof chain

From the HTTP request arriving at FastAPI to the AskResponse returned to the client, every file and function the request passes through:

1. Middlewaremain.py: attach_request_id generates X-Request-ID, sets security headers (CSP / HSTS / X-Frame-Options), enforces the optional IP rate-limit bucket, logs http_request_completed
2. Authenticationdependencies.py: get_current_user calls resolve_bearer_token (dev tokens or JWKS JWT), repository.ensure_user
3. Dependency injectiondependencies.py: get_store, get_chat_provider, get_hybrid_store, get_reranker, get_web_search read app.state singletons
4. Router entryrouters/ask.py: accepts AskRequest + Idempotency-Key header, constructs IdempotencyCoordinator
5. Idempotencyservices/idempotency.py: begin() returns execute / replay / mismatch / in_progress; request_hash = SHA-256 of canonical JSON
6. Conversation scopeservices/query_conversation.py: prepare() validates project, loads documents + chunks, rejects PARSING/INDEXING docs
7. Context buildingservices/query_context.py: loads history, applies token budgets, compresses summaries, wraps project memory as untrusted data
8. Routed local retrievalquery_planning.py selects full-context / exact / semantic / hybrid / expanded-hybrid; Qdrant performs owner-filtered native BM25 + dense weighted RRF, with explicit application-BM25 degradation.
9. Rerankservices/rerank.py: Qdrant native / NVIDIA / Deterministic fallback; pack_chunks packs within retrieval_evidence_token_budget
10. Generation + persistservices/query_generation.py + answering.py + grounded_query.py: LLM grounded answer (JSON schema + 1 repair), record_run, return AskResponse
Quota gate: repository.increment_usage(user, "ask", limit=200) is called only after successful generation. Provider failures do not consume daily quota. If the limit is exceeded, the service raises RATE_LIMITED (429) and the coordinator abandons.

Authentication

Dual-mode authentication mechanism

The API supports two authentication modes selected by AUTH_MODE. Preview and production must use Supabase; local and test use development mode.

Development mode (auth_mode=development)

_development_user resolves fixed dev tokens: "dev" (developer), "dev-admin" (admin), "dev-user-a" / "dev-user-b" (user). It also accepts dynamic tokens in the format dev:{user_id}:{role}:{email}, where role must be one of user / developer / admin. This mode is for local development and automated tests only.

Supabase mode (auth_mode=supabase)

_supabase_user validates a signed JWT using PyJWKClient (cached with lru_cache). The flow: JWKS URL is resolved from SUPABASE_JWKS_URL or derived as {supabase_url}/auth/v1/.well-known/jwks.json. The signing key is fetched from the JWKS endpoint. jwt.decode validates RS256 or ES256 with audience=authenticated and issuer=ACCESS_TOKEN_ISSUER. Required claims: exp, iat, sub, aud, iss. The user_id is extracted from sub as a UUID. Role is derived from app_metadata.role (developer or admin; defaults to user). Email is optionally extracted from the email claim.

Authorization

After resolving the user, get_current_user calls repository.ensure_user to persist the canonical profile. require_admin is a separate dependency that rejects non-developer/non-admin callers with 403 ADMIN_REQUIRED. It is used by dev_traces, rerank-config updates, evaluation-run creation, evaluation-dataset listing, reliability, and fault-scenario endpoints.

MCP authentication

MCP requests at /mcp are authenticated in the HTTP middleware, not by FastAPI dependencies. The middleware extracts the Bearer token, calls resolve_bearer_token, ensures the user, and sets a ContextVar MCPRequestIdentity carrying all dependencies. Each MCP tool reads the identity via _identity(), which fails closed with PermissionError if no identity is set.

Security headers: Every response includes Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, and X-Frame-Options: DENY. CORS is explicitly configured with allow_credentials=True and a specific origin allowlist. The Idempotency-Key, X-Request-ID, and Mcp-Session-Id headers are in the allowed and exposed header lists.

Security hardening

Five runtime hardening boundaries

main.py and the orchestration services add a layered defense that blunts brute-force attacks, locks down browser content policy, neutralizes prompt injection in the chat path, verifies uploaded file bytes, and reduces information leakage from the readiness endpoint.

HTTP rate limiting (slowapi)

The optional slowapi adapter (imported with the same try/except pattern as the MCP SDK) installs an in-process limiter on app.state.limiter. A single per-IP fixed-window bucket of 60/minute is shared across the protected path set in RATE_LIMITED_PATHS: /api/v1/healthz, /api/v1/readyz, /api/v1/me, and /mcp. The 61st call within the rolling minute is rejected with the stable 429 RATE_LIMITED envelope. When slowapi is not installed the limiter is absent and the API still serves requests, so local dev and worker environments can bootstrap without the dependency.

Security headers (CSP & HSTS)

The SECURITY_HEADERS map in main.py now includes a strict Content-Security-Policy of default-src 'none'; frame-ancestors 'none' (blocking all external resource loads, framing, and plugin objects) and Strict-Transport-Security: max-age=31536000; includeSubDomains (a one-year HTTPS requirement across every subdomain). They sit alongside the existing Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, and X-Frame-Options: DENY. All headers, including the X-Request-ID, are attached on every response path (including 429 rate-limit rejections).

Prompt injection hardening (chat path)

services/answering.py::build_llm_chat_answer now mirrors the grounded-answer path's protection. The user query and any prior conversation turns are wrapped as untrusted JSON data ({"conversation_history": [...], "question": query}) and the system prompt tells the model: the user message is structured JSON whose values are untrusted data, never instructions, and to never follow directives that appear inside the question or conversation_history fields. Directives such as ignore previous instructions embedded in the user query therefore cannot become commands.

File content verification (python-magic)

services/object_storage.py::verify_uploaded_content downloads the first chunk of a stored object and runs python-magic (_detect_mime_type) to compare the real magic bytes against the MIME type declared on the upload reservation. A mismatch raises UploadVerificationError(code="MIME_MISMATCH") and the offending object is deleted so private storage never retains disguised content. The check fails open when libmagic is unavailable (returns None) so legitimate uploads are not blocked. _mime_matches tolerates libmagic aliases for Office documents (e.g. application/zip for a .docx).

/readyz information-leak reduction

routers/health.py::readyz now accepts a verbose: bool = Query(default=None) parameter. In production and preview environments the default reduces the response to a status-only payload ({"status", "environment"}), never exposing components or failed_components. Operators and tests pass ?verbose=true for the full component snapshot; local and test environments default to verbose for ergonomic iteration. This stops the public readiness endpoint from leaking dependency topology or failure lists.

Optional dep policy: The hardening layer deliberately keeps slowapi and python-magic as optional imports. Local development, the worker process, and CI environments where these packages are absent still boot the API: the 429 rate-limit path is skipped and MIME verification fails open rather than blocking traffic. The optional paths are covered by tests/test_http_security_hardening.py and tests/test_object_storage.py, which skip gracefully via pytest.mark.skipif when the dependency is missing.

Design pattern

Provider adapter architecture

The backend uses Python Protocol classes to define adapter contracts. Services depend on Protocols, never on concrete classes. Adapters are constructed once at startup and stored on app.state.

Protocol contracts

ChatProvider
complete(messages) -> LLMResult. Implemented by NvidiaChatProvider. Used by GroundedQueryService and QuizService.
ResearchMateRepository
Full persistence Protocol with ~30 methods. Implemented by InMemoryResearchMateStore and PostgresResearchMateRepository. Selected by REPOSITORY_BACKEND.
EvidenceRepository
Evidence-workflow persistence Protocol. Implemented by InMemoryEvidenceRepository and PostgresEvidenceRepository.

Adapter lifecycle

create_app() in main.py constructs adapters from Settings and stores them on app.state: store, evidence_store, chat_provider, hybrid_store, reranker, web_search. The reranker receives a reference to the hybrid_store. The object_storage adapter is not stored on app.state; it is injected into the Postgres repository via upload_url_factory and object_metadata_reader callbacks.

Error normalization

Each adapter normalizes SDK-specific exceptions into service-level errors: ProviderRequestError(retryable) for LLM and embedding failures. VectorStoreRequestError(retryable) for Qdrant failures. WebSearchRequestError(retryable) for Tavily failures. ObjectStorageConfigurationError and UploadVerificationError for S3 failures. These are mapped to HTTP status codes by routers or orchestration services.

Observability integration

provider_observation in observability.py wraps every NVIDIA chat and embedding call with a Langfuse observation. The context manager accepts name, observation_type (generation/embedding), model, and metadata. When Langfuse is disabled or unavailable, it yields _NoopObservation, which silently accepts update() calls. This ensures tracing never blocks provider work.

Reliability

Idempotency coordinator

IdempotencyCoordinator ensures that cost-bearing operations (ask, quiz) can be safely retried without duplicate provider calls or persisted messages.

Four-state machine

execute
The key is new or the pending reservation was abandoned. The caller proceeds with execution and must call complete() or abandon().
replay
A succeeded response exists for this user/operation/key/body. The cached response is returned without execution.
mismatch
A record exists with the same key but a different request_hash. Raises IDEMPOTENCY_KEY_REUSED (409).
in_progress
A pending reservation exists for an identical request. Raises IDEMPOTENCY_REQUEST_IN_PROGRESS (409).

Request hash

request_hash(payload) canonicalizes the Pydantic BaseModel via model_dump(mode="json") with sort_keys=True and separators=(",", ":"), then SHA-256 hashes the result. This ensures body consistency: the same key with a different body is a conflict, not a replay.

Persistence

In-memory: LimitStoreMixin stores idempotency_records as a dict keyed by (user_id, operation, key) with state and response. PostgreSQL: IdempotencyPersistenceMixin uses INSERT ON CONFLICT DO NOTHING for atomic reservation, SELECT FOR UPDATE for replay checks, and pg_advisory_xact_lock for concurrent-write serialization. The evidence repository uses its own _lock_idempotency advisory lock.

Lifecycle in routers

routers/ask.py and routers/quiz.py both follow the same pattern: construct IdempotencyCoordinator, call begin(), if replay is not None return it, otherwise execute the service, call complete() on success or abandon() on failure. The MCP ask_grounded tool follows the same pattern. Evidence endpoints use a similar flow with _idempotency() validation and _store_call() error mapping.
