CI/CD . 流水线与部署

ResearchMate 通过五 Job 的 GitHub Actions 流水线对每次 push 和 pull request 进行门控,用两个多阶段 Dockerfile 产出加固的容器镜像,并通过单个 Render Free 服务在 CI 检查通过后自动部署。本页逐文件解析定义构建、测试、扫描与部署生命周期的全部配置文件。

5 个 CI Job 2 个 Dockerfile render.yaml 中 48 个环境变量 11 个 sync:false 密钥 checksPass 自动部署 双锁策略: uv.lock + package-lock.json

技术栈基础

定义构建与部署生命周期的 7 个工具

每张卡片说明该工具的通用职责,以及 ResearchMate 中的具体用法。

CI/CD

持续集成 / 持续部署 (Continuous Integration / Continuous Deployment) 是通过可复现的流水线自动测试、构建、扫描并部署每次代码变更的实践。ResearchMate 将 CI 视为发布就绪的唯一事实来源:除非全部五个门控 Job 通过且 ci-success 聚合器确认每个结果均为 success,否则任何 commit 都不会进入生产环境。

GitHub Actions

工作流自动化平台,在 push 到 main 或 develop 以及每个 pull request 时触发。researchmate-ci 工作流使用 concurrency group 配合 cancel-in-progress 取消过时运行,将每个 action 固定到主版本号,并运行五个具有显式 timeout-minutes(20 至 35 分钟)的 Job。ci-success Job 使用 if: always() 配合 needs 聚合全部四个质量门控。

Docker

容器化引擎,产出可复现的运行时镜像。两个 Dockerfile 均使用多阶段构建,固定 uv 阶段并以 python:3.13-slim 为基础镜像。分层 COPY 指令将依赖清单与源码分离以最大化构建缓存命中。API 镜像以非 root 用户(uid 10001)运行;worker 镜像额外安装系统库并预下载 Docling 模型。CI 使用 hadolint 和 Trivy 验证两者。

Render

云部署平台,将合并的 backend-plus-worker 服务作为单个 Free 层 Docker web 服务托管在 Oregon 区域。render.yaml 声明一个包含 48 条目的 envVarGroups 块(37 条带值,11 条 sync:false 密钥),autoDeployTrigger 设为 checksPass,并使用 buildFilter 将重建限制在相关路径变更时触发。healthCheckPath /api/v1/readyz 确认运行时就绪。

Vercel

apps/web 中 Next.js 16.3.0 前端应用的部署平台。Vercel 独立于后端构建并服务生产前端。render.yaml 中的 CORS_ALLOWED_ORIGINS 设为 Vercel 源地址,使 API 接受来自已部署前端的浏览器请求。

uv

Astral 开发的 Python 包管理器与项目管理器,在 CI 和 Dockerfile 中固定为 0.12.1 版本。uv 解析 monorepo workspace(apps/api + workers/ai-worker),通过 uv.lock 以 --frozen 标志安装锁定依赖,并支持 --all-packages 在一条命令中安装所有 workspace 成员。setup-uv action 在 CI 中启用缓存以加速运行。

npm workspaces

JavaScript monorepo 管理方案,通过根 package.json 中的 packageManager 声明 npm@11.6.0。workspaces 数组包含 apps/web。CI 运行 npm install --no-audit --no-fund 安装完整 workspace 树,package-lock.json 锁文件保证本地与 CI 环境间的可复现 JavaScript 依赖解析。

CI/CD 工作流

从 commit 到线上:五个质量流与部署提升链

每次 push 到 main/develop 以及每个 pull request 都遵循同一条门禁链。状态转换遵循 planned → ready → executed → verified 四态模型:前四个并行门控 Job 在 ready 阶段验证源 artifact，ci-success 聚合门禁在 verified 阶段确认全部成功。只有聚合门禁通过后，Render 的 autoDeployTrigger: checksPass 才触发生产部署提升——在 CI 绿灯与生产部署之间建立硬依赖。

为什么这个拓扑有效

四个独立质量流并行运行而非串行，将墙钟时间从 100 分钟压缩到 35 分钟（最长路径）。ci-success 聚合门禁使用 if: always() 确保即使上游失败也显式报告结果，而非静默跳过。Render 的 checksPass 在 CI 绿灯与生产部署之间建立硬依赖——绿色 build 不等于已提升，只有聚合门禁通过才触发部署。buildFilter 将重建限制在相关路径变更，避免纯文档变更触发不必要的后端重建。

Dockerfile . API

apps/api/Dockerfile . 两阶段、非 root、内置健康检查

API Dockerfile 产出在 Render 管理的代理后运行 uvicorn 的精简生产镜像。它优先考虑缓存效率、最小权限执行和内置健康验证。

多阶段构建

阶段 1 从 ghcr.io/astral-sh/uv:0.12.1 复制 uv 和 uvx 二进制文件。阶段 2 在 python:3.13-slim 上构建运行时。uv 二进制作为静态资源复制,因此最终镜像不携带构建工具链。

非 root 用户

创建专用组 researchmate(gid 10001)和用户(uid 10001),使用 --no-create-home --shell /usr/sbin/nologin。USER 10001:10001 指令确保进程在容器内永不以 root 身份运行。

分层 COPY

依赖清单在源码之前复制:先 pyproject.toml uv.lock,然后 apps/api/pyproject.toml 和 workers/ai-worker/pyproject.toml,最后 apps/api 源码。此顺序让 Docker 缓存 uv sync 层,仅在依赖变更时才失效。

uv sync

uv sync --frozen --no-dev --package researchmate-api 精确安装 API workspace 成员的锁定生产依赖,跳过 dev 工具并拒绝锁文件漂移。

HEALTHCHECK

--interval=30s --timeout=5s --start-period=20s --retries=3 调用 python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/api/v1/healthz', timeout=3)"。连续三次失败将容器标记为 unhealthy。

CMD (shell form)

sh -c "exec python -m uvicorn researchmate_api.main:app --host 0.0.0.0 --port ${PORT:-8000} --workers 2 --proxy-headers"。必须使用 shell form 以安全展开 Render 运行时 PORT 值。--proxy-headers 标志信任 Render 负载均衡器的 X-Forwarded-* 头。

FROM ghcr.io/astral-sh/uv:0.12.1 AS uv FROM python:3.13-slim AS runtime COPY --from=uv /uv /uvx /bin/ RUN groupadd --gid 10001 researchmate \ && useradd --uid 10001 --gid researchmate --no-create-home --shell /usr/sbin/nologin researchmate COPY pyproject.toml uv.lock /app/ COPY apps/api/pyproject.toml /app/apps/api/pyproject.toml COPY workers/ai-worker/pyproject.toml /app/workers/ai-worker/pyproject.toml COPY apps/api /app/apps/api RUN uv sync --frozen --no-dev --package researchmate-api USER 10001:10001 EXPOSE 8000 HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \ CMD ["python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/api/v1/healthz', timeout=3)"] CMD ["sh", "-c", "exec python -m uvicorn researchmate_api.main:app --host 0.0.0.0 --port ${PORT:-8000} --workers 2 --proxy-headers"]

Dockerfile . Worker

workers/ai-worker/Dockerfile . 三阶段、系统依赖、角色切换

worker Dockerfile 构建 Render Free 层使用的 CPU-only 合并 backend-plus-worker 运行时。它添加 Docling 所需的系统库,预下载 ML 模型,并通过环境变量在 dispatcher 和 worker 角色之间切换。

三个阶段

阶段 1 (uv) 复制 uv 二进制。阶段 2 (dependencies) 在 python:3.13-slim 上安装系统包和 Python 依赖。阶段 3 (runtime) 继承 dependencies,下载 Docling 模型并设置所有权,将模型制品保留在单独的可缓存层中。

系统依赖

apt-get install --yes --no-install-recommends libgl1 libglib2.0-0 提供 Docling 和 OpenCV 进行 PDF 渲染与图像处理所需的共享库。apt 缓存立即清理以最小化镜像大小。

Docling 模型

docling-tools models download layout tableformer rapidocr -o /opt/docling/models 将三个模型包预取到 DOCLING_ARTIFACTS_PATH=/opt/docling/models。chown -R researchmate:researchmate /opt/docling 确保非 root 用户在运行时可以读取它们。

--all-packages

uv sync --frozen --no-dev --all-packages 在一个解析图中安装每个 workspace 成员(researchmate-api + researchmate-worker)。这是必需的,因为 Render 通过 python -m researchmate_worker.render_combined 运行合并运行时,该模块导入两个包。

角色切换

CMD 检查 RESEARCHMATE_PROCESS_ROLE。当设为 dispatcher 时,运行 exec researchmate-dispatch-outbox。否则启动 Celery worker,消费 5 个队列(ingestion, deletion, workflow, evaluation, reliability),设置 --concurrency=2。

torch CPU index

worker 的 pyproject.toml 通过 [tool.uv.sources] 指向 pytorch-cpu index,固定 torch==2.13.0+cpu 和 torchvision==0.28.0+cpu。这避免在没有 GPU 的 Free 层主机上拉取 CUDA 驱动。

FROM ghcr.io/astral-sh/uv:0.12.1 AS uv FROM python:3.13-slim AS dependencies COPY --from=uv /uv /uvx /bin/ RUN apt-get update \ && apt-get install --yes --no-install-recommends libgl1 libglib2.0-0 \ && rm -rf /var/lib/apt/lists/* COPY pyproject.toml uv.lock /app/ COPY apps/api /app/apps/api COPY workers/ai-worker /app/workers/ai-worker RUN uv sync --frozen --no-dev --all-packages FROM dependencies AS runtime RUN docling-tools models download layout tableformer rapidocr -o /opt/docling/models \ && chown -R researchmate:researchmate /opt/docling USER 10001:10001 CMD ["sh", "-c", "if [ \"${RESEARCHMATE_PROCESS_ROLE:-worker}\" = dispatcher ]; then exec researchmate-dispatch-outbox; \ else exec python -m celery -A researchmate_worker.celery_app:celery_app worker --loglevel=INFO \ --queues=ingestion,deletion,workflow,evaluation,reliability --concurrency=2; fi"]

render.yaml

Render 部署蓝图 . 48 个环境变量,1 个服务,CI 通过后自动部署

render.yaml 声明唯一的 Render Free 层服务及其完整环境配置。它将 48 个环境变量集中到一个命名组中,将重建限制在相关路径,并仅在 GitHub 检查通过后触发部署。

依赖管理

Python 与 JavaScript 的双锁策略

ResearchMate 使用两个独立的锁文件管理依赖:Python workspace 的 uv.lock 和 npm workspace 的 package-lock.json。两者都提交到仓库,并在 CI 和 Docker 中使用 --frozen 标志保证可复现安装。

根 package.json

声明 packageManager: npm@11.6.0 和 workspaces: ["apps/web"]。定义 17 个脚本,包括 test:python、test:web、test:e2e、check:lint、check:openapi、check:migrations、check:web、check:audit 以及总括脚本 check:all。private 标志防止意外 npm 发布。

根 pyproject.toml

.env.example

7 大类环境配置

.env.example 文件记录运行时接受的每个变量,分为七个类别。密钥使用占位符,非密钥配置使用安全默认值。

类别关键变量说明
1. Frontend public APP_ENV, AUTH_MODE, NEXT_PUBLIC_APP_ENV, NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, NEXT_PUBLIC_API_BASE_URL 通过 NEXT_PUBLIC_ 前缀暴露给浏览器。本地开发使用 AUTH_MODE=development。
2. Database & Supabase REPOSITORY_BACKEND, DATABASE_URL, SUPABASE_URL, SUPABASE_JWKS_URL 本地开发默认使用 memory backend。生产使用 postgres 配合 JWKS 进行 JWT 验证。
3. Object storage OBJECT_STORAGE_ENDPOINT_URL, OBJECT_STORAGE_ACCESS_KEY_ID, OBJECT_STORAGE_SECRET_ACCESS_KEY, OBJECT_STORAGE_BUCKET, OBJECT_STORAGE_REGION S3 兼容。Supabase Storage 是无需信用卡的开发默认值;R2 旧变量仍受支持。
4. Vector database QDRANT_URL, QDRANT_API_KEY, QDRANT_COLLECTION, QDRANT_RERANK_COLLECTION, QDRANT_RERANK_MODEL, QDRANT_RERANK_DIMENSION, RERANK_PROVIDER_DEFAULT, NVIDIA_RERANK_MODEL, CHAT_*_TOKEN_BUDGET, FULL_CONTEXT_TOKEN_LIMIT Rerank 模型: answerdotai/answerai-colbert-small-v1,维度 96。Token 预算控制上下文窗口分区。
5. LLM & embedding LLM_PROVIDER, NVIDIA_API_KEY, NVIDIA_BASE_URL, NVIDIA_MODEL, LLM_TEMPERATURE, LLM_MAX_TOKENS, EMBEDDING_PROVIDER, NVIDIA_EMBEDDING_MODEL, EMBEDDING_DIMENSION 本地开发使用 fake provider。生产使用 NVIDIA NIM,配合成本跟踪变量。
6. Search & crawl WEB_SEARCH_PROVIDER, TAVILY_API_KEY, TAVILY_BASE_URL, WEB_SEARCH_TIMEOUT_SECONDS 本地禁用。生产使用 Tavily,30 秒超时。
7. Runtime, jobs & observability REDIS_URL, RUNTIME_HEARTBEAT_SECONDS, WORKFLOW_LEASE_SECONDS, RESEARCHMATE_PROCESS_ROLE, CORS_ALLOWED_ORIGINS, MAX_UPLOAD_BYTES, DOCLING_ARTIFACTS_PATH, LANGGRAPH_STRICT_MSGPACK, LOG_LEVEL, OTEL_ENABLED, OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, LANGFUSE_ENABLED, LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY 本地禁用可观测性(OTEL_ENABLED=false, LANGFUSE_ENABLED=false)。在 preview/production 中必需且单独密钥化。
