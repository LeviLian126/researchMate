后端 . apps/api

ResearchMate 后端是一个 FastAPI 应用,对外提供 45 个 REST 操作(/api/v1 前缀)和 6 个 MCP tools(Streamable HTTP)。它负责认证、grounded-query 编排、Provider 适配器、幂等协调,以及内存 / PostgreSQL 双持久化层。本页逐文件解析 apps/api/src/researchmate_api/ 下的全部源码。

5 个核心文件 11 个 routers 10 个 schemas 35 个 services 19 个 persistence 6 MCP tools . 3 MCP resources

技术栈基础

驱动后端的 12 个依赖

每张卡片说明该库的通用职责,以及 ResearchMate 中的具体用法。

FastAPI

组装 REST API 的 Web 框架。main.py 创建应用实例,配置 lifespan、CORS 中间件、自定义 request-id 中间件、通过 response_model 实现的类型化错误响应,以及自动 OpenAPI schema。11 个 routers 全部挂载在 /api/v1 下。

Pydantic

为每个请求和响应提供数据校验。BaseModel 子类通过 Field 约束(min_length、max_length、ge、le)、ConfigDict(extra="forbid")禁止多余字段、model_validator 实现跨字段校验、use_enum_values 保证 JSON 序列化稳定。

SQLAlchemy

管理 PostgreSQL 引擎的 SQL 工具包。create_engine 配置 pool_pre_ping 和 pool_recycle=300 保持连接健康。通过 text() 执行原生 SQL,在 context manager 事务中注入 RLS 参数 request.jwt.claim.sub。

psycopg

PostgreSQL 适配器。_psycopg_url 辅助函数将 postgres:// 和 postgresql:// 归一化为 postgresql+psycopg://,使 SQLAlchemy 使用同步 psycopg 驱动。所有数据库操作均为同步,需要时通过 anyio.to_thread 卸载到线程池。

PyJWT

用于 Supabase 认证的 JWT 验证。PyJWKClient 缓存 JWKS 签名密钥。decode 验证 RS256 或 ES256 算法,检查 audience 和 issuer。必需 claims:exp、iat、sub、aud、iss。角色从 app_metadata.role 派生,默认为 user。

Qdrant

用于混合检索的向量数据库。QdrantClient 通过 RRF 融合 dense 和 sparse 向量,强制 owner-scoped payload 过滤(user_id、project_id、source_type),并在专用 rerank collection 中支持基于 Document 模型的 late-interaction 重排。

OpenTelemetry

分布式链路追踪。OTLPSpanExporter 将 span 发送到 collector 端点。FastAPIInstrumentor 自动插桩应用。Resource 标记 service.name 和 deployment.environment.name。tracer provider 由 ObservabilityRuntime 拥有,在退出时安全关闭。

Langfuse

LLM 可观测性。provider_observation 为每次 NVIDIA chat 和 embedding 调用创建 generation 或 embedding observation,记录模型、输入元数据和使用量。LANGFUSE_ENABLED 为 false 时回退到 _NoopObservation。

OpenAI SDK

NVIDIA NIM 端点的客户端。OpenAI(base_url=nvidia_base_url, api_key, timeout, max_retries=0) 用于 chat.completions.create 和 embeddings.create。SDK 被 NvidiaChatProvider 和 NvidiaEmbeddingProvider 封装,services 层从不直接调用。

boto3

S3 兼容对象存储客户端。S3CompatibleObjectStorage 封装 boto3.client("s3"),提供 presign_upload(签名 PUT URL)和 head(读取对象元数据)。支持 Cloudflare R2(账户级 endpoint)或任意通用 S3 endpoint。

httpx

OpenAI SDK 和 Tavily web search provider 使用的 HTTP 传输层。提供同步 HTTP 请求和可配置超时。Tavily 适配器向 api.tavily.com 发送搜索查询,将结果归一化为 ChunkEntry 对象。

MCP

Model Context Protocol 服务端。FastMCP 通过 Streamable HTTP 暴露 6 个 tools(list_projects、search_project、search_conversation、ask_grounded、get_run_trace、run_evaluation)和 3 个 resources(project documents、conversation documents、run summary),使用与 REST 相同的 bearer 中间件认证。

核心文件

引导 API 的五个文件

这些文件负责应用组装、配置校验、认证、MCP 接口和可观测性生命周期。

main.py . create_app()

应用工厂函数。构建 FastAPI 实例,lifespan 管理 MCP session manager 和 observability 关闭流程。适配器从 Settings 解析后存储在 app.state 上:store(ResearchMateRepository)、evidence_store(EvidenceRepository)、chat_provider(NvidiaChatProvider 或 None)、hybrid_store(QdrantHybridStore 或 None)、reranker(RerankCoordinator)、web_search(TavilyWebSearchProvider 或 None)。自定义 HTTP 中间件为每个响应附加 X-Request-ID 和安全 headers(Cache-Control: no-store、Referrer-Policy: no-referrer、X-Content-Type-Options: nosniff、X-Frame-Options: DENY),在 /mcp 路径认证 MCP 请求,并记录结构化 http_request_completed 事件(含延迟)。两个异常处理器将 HTTPException 和 RequestValidationError 映射到统一的 ErrorResponse 信封。11 个 routers 挂载在 /api/v1 下。若 MCP SDK 已安装,其 ASGI 应用挂载在 /mcp;否则返回 503 MCP_RUNTIME_NOT_INSTALLED。

config.py . Settings

基于 pydantic-settings 的 BaseSettings 类,校验所有运行时配置项。关键分组:环境(app_env: local/test/preview/production)、认证(auth_mode: development/supabase)、仓库(memory/postgres)、LLM(nvidia 模型、temperature、top_p、max_tokens、seed、timeout)、embedding(4096 维 NVIDIA nv-embed-v1)、Qdrant(collection、rerank collection、rerank model)、rerank(auto/qdrant/nvidia/deterministic,candidate_limit=50、top_n=10)、token 预算(chat_history=5000、recent=3500、summary=1500、full_context=12000、retrieval_evidence=8000)、web search(tavily)、CORS、可观测性(OTEL + Langfuse)、对象存储(R2 或通用 S3)。model_validator(mode="after") 拒绝不安全的组合:preview/production 必须使用 Supabase 认证、PostgreSQL、Redis、对象存储、NVIDIA LLM + embedding、Qdrant、Tavily 和 Langfuse。get_settings() 使用 lru_cache 缓存。

dependencies.py

FastAPI 依赖提供者和认证逻辑。get_store、get_chat_provider、get_hybrid_store、get_web_search、get_reranker、get_evidence_store 从 request.app.state 读取单例。get_current_user 通过 resolve_bearer_token 解析 bearer token,根据 auth_mode 分发到 _development_user(固定 dev token 或 dev:user_id:role:email 格式)或 _supabase_user(JWKS 验证 JWT,RS256/ES256)。解析用户后调用 repository.ensure_user 持久化规范化 profile。require_admin 限制 developer/admin 角色路由。错误辅助函数(error_detail、raise_api_error、not_implemented_detail)构建全局异常处理器消费的统一错误信封。

mcp_server.py . build_mcp_server()

构建无状态 FastMCP 服务端,暴露 6 个 tools 和 3 个 resources。Tools:list_projects、search_project、search_conversation、ask_grounded(完整 GroundedQueryService 执行 + IdempotencyCoordinator)、get_run_trace(admin 限制)、run_evaluation(admin 限制)。Resources:project://{project_id}/documents、conversation://{conversation_id}/documents、run://{run_id}。每个请求由 main.py 中间件认证,设置 ContextVar MCPRequestIdentity 携带 user、repository、evidence store、providers 和 settings。_identity() 辅助函数在未设置 identity 时抛出 PermissionError(失败关闭)。服务端使用 stateless_http=True 和 json_response=True。

observability.py

配置隐私安全的日志和可选遥测。log_event 通过 researchmate logger 发送有界 JSON 事件(绝不包含 prompt、token 或文档文本)。configure_observability 可选启动 OpenTelemetry(OTLPSpanExporter + BatchSpanProcessor + FastAPIInstrumentor)和 Langfuse(get_client)。ObservabilityRuntime 拥有 tracer provider 和 Langfuse client,在 lifespan 退出时 flush 并关闭。provider_observation 是一个 context manager,用 Langfuse generation/embedding observation 包装 provider 调用;追踪禁用或 exporter 不可用时 yield _NoopObservation。

routers/ . 11 个文件

Router 逐文件详解

每个 router 是一个轻量 HTTP 适配器,负责认证、委托 service、将错误映射为统一 API 信封。

ask.py
POST /ask。统一 Ask 端点。接受 AskRequest 和可选的 Idempotency-Key header(8-160 字符)。构造 IdempotencyCoordinator,调用 begin() 检查是否可重放,执行 GroundedQueryService.execute(),然后调用 complete() 或 abandon()。IdempotencyError 映射为 409,GroundedQueryError 映射为对应状态码。
conversations.py
8 个端点。列出全部会话、在项目中创建/列出会话、列出消息(上限 200 条)、重命名、删除(含附件清理,原子操作),以及两个 admin 专属 rerank-config 路由(GET + PUT 乐观版本检查)。PUT 在激活前验证 Qdrant rerank 就绪状态。
dev_traces.py
GET /dev/traces/{trace_id}。Admin 专属端点,通过 TraceQueryService 返回脱敏的 DeveloperTrace,执行与 MCP 共享的 developer/admin 角色策略。
documents.py
7 个端点。上传地址预约(签名 PUT)、创建文档元数据、列出项目/会话文档、读取单个文档、完成上传(验证对象元数据、入队 ingestion job、接受仅本地 extracted_text)、删除文档(入队删除 job)。UploadVerificationError 映射为 409,ObjectStorage 错误映射为 503。
evidence.py
Evidence 工作流端点。创建幂等 research run(202)、读取 workflow run、SSE 流式 run events、列出/读取 reports、列出 pipeline versions、列出 evaluation datasets(admin)、创建 evaluation run(admin)、刷新 report(202)、读取 reliability 聚合(admin)、创建/读取 fault scenario(admin,仅非生产环境)。所有异步写入需要 8-160 字符 Idempotency-Key。
health.py
GET /healthz + GET /readyz。healthz 不触碰任何依赖直接返回 ok。readyz 探测数据库(select 1 + checkpoint 表 + heartbeats + outbox 积压)、Redis(ping)、Qdrant(get_collection)、对象存储、LLM、web search。任一必需依赖不可用时返回 503 和 failed_components 列表。
jobs.py
GET /jobs/{job_id}。仅返回认证调用者拥有的 JobRecord。
me.py
GET /me。返回 get_current_user 建立的 CurrentUser。最简单的 router:一个依赖,一个响应。
projects.py
5 个端点。POST /chat/bootstrap 返回隐藏的 personal project。POST /projects 创建 workspace 项目。GET /projects 列出拥有的 workspace。GET /projects/{id} 返回单个项目。DELETE /projects/{id} 入队清理(202)。
quiz.py
POST /quiz + GET /projects/{id}/quiz。POST 通过 QuizService 生成可溯源 Quiz,配合 IdempotencyCoordinator。GET 列出项目已保存的 QuizSet。QuizServiceError 映射为对应状态码(404、409、429、503)。
runs.py
GET /runs/{run_id}/sources。返回调用者可见 run 的 Sources 面板数据(RunSourcesResponse,含引用摘要和已验证 citations)。

services/ . 编排服务组(15 个文件)

应用编排服务

这些服务协调业务逻辑,不拥有适配器机制。它们依赖 ResearchMateRepository protocol 和 provider Protocols,从不依赖具体适配器类。

grounded_query.py
GroundedQueryService。统一 Ask 编排器。execute() 运行完整管线:准备会话 scope、检索本地 evidence(BM25 + Qdrant)、可选检索 web evidence、rerank 候选、生成回答(grounded 或 chat)、增加使用配额、记录 run 和 trace。为每个阶段构建 ToolCallTrace,将 runtime_metadata(context_strategy、rerank provider/model、token 估算、延迟)打包到持久化 trace 中。
answering.py
回答构建器,三种模式。build_llm_grounded_answer:构建 evidence JSON(含服务端分配的 evidence_id 整数),校验 provider 输出是否符合 GroundedAnswerProposal schema,允许一次 schema 修复,将 evidence_ids 映射为 Citation 对象。build_grounded_answer:从 chunks 生成确定性本地回答。build_llm_chat_answer / build_chat_answer:无 evidence 的纯聊天。_extract_json_object 处理 markdown-fenced LLM 输出。
query_context.py
ConversationContextBuilder。加载会话历史,应用 token 预算(recent=3500、summary=1500、trigger=8000),将旧消息压缩为 LLM 生成的摘要,并将跨会话 project memory 作为不可信数据包装在 XML-like 块中。bound_messages 在硬 token 预算内保留最新消息。_truncate_to_budget 裁剪超长消息。
query_conversation.py
QueryConversationCoordinator。prepare() 验证项目 active 状态、解析已有会话、加载文档和 chunks(workspace vs personal scope)、拒绝仍处于 PARSING/INDEXING 状态的文档、构建会话 context。ensure_for_commit() 仅在生成成功后创建会话,避免失败时留下空会话。
query_errors.py
GroundedQueryError 异常,携带 code、message 和 status_code。raise_grounded_error 辅助函数。所有 query_* 模块共享,在不耦合 HTTP 的情况下传播稳定错误。
query_execution.py

认证机制

双模式认证机制

API 支持由 AUTH_MODE 选择两种认证模式。Preview 和 production 必须使用 Supabase;local 和 test 使用 development 模式。

Development 模式(auth_mode=development)

_development_user 解析固定 dev token:"dev"(developer)、"dev-admin"(admin)、"dev-user-a" / "dev-user-b"(user)。也接受格式为 dev:{user_id}:{role}:{email} 的动态 token,其中 role 必须为 user / developer / admin 之一。此模式仅用于本地开发和自动化测试。

Supabase 模式(auth_mode=supabase)

_supabase_user 使用 PyJWKClient(通过 lru_cache 缓存)验证签名 JWT。流程:JWKS URL 从 SUPABASE_JWKS_URL 解析,或从 {supabase_url}/auth/v1/.well-known/jwks.json 派生。从 JWKS 端点获取签名密钥。jwt.decode 验证 RS256 或 ES256,检查 audience=authenticated 和 issuer=ACCESS_TOKEN_ISSUER。必需 claims:exp、iat、sub、aud、iss。user_id 从 sub 提取为 UUID。角色从 app_metadata.role 派生(developer 或 admin,默认 user)。Email 可选地从 email claim 提取。

授权

解析用户后,get_current_user 调用 repository.ensure_user 持久化规范化 profile。require_admin 是独立依赖,拒绝非 developer/non-admin 调用者(403 ADMIN_REQUIRED)。用于 dev_traces、rerank-config 更新、evaluation-run 创建、evaluation-dataset 列出、reliability 和 fault-scenario 端点。

MCP 认证

/mcp 路径的 MCP 请求在 HTTP 中间件中认证,而非通过 FastAPI 依赖。中间件提取 Bearer token,调用 resolve_bearer_token,ensure user,然后设置 ContextVar MCPRequestIdentity 携带所有依赖。每个 MCP tool 通过 _identity() 读取 identity,未设置时抛出 PermissionError(失败关闭)。

安全 headers: 每个响应包含 Cache-Control: no-store、Referrer-Policy: no-referrer、X-Content-Type-Options: nosniff 和 X-Frame-Options: DENY。CORS 显式配置 allow_credentials=True 和特定 origin 白名单。Idempotency-Key、X-Request-ID 和 Mcp-Session-Id headers 在允许和暴露的 header 列表中。

后端使用 Python Protocol 类定义适配器契约。Services 依赖 Protocols,从不依赖具体类。适配器在启动时构造一次并存储在 app.state 上。

适配器生命周期

main.py 中的 create_app() 从 Settings 构造适配器并存储在 app.state 上:store、evidence_store、chat_provider、hybrid_store、reranker、web_search。reranker 接收 hybrid_store 的引用。object_storage 适配器不存储在 app.state 上,而是通过 upload_url_factory 和 object_metadata_reader 回调注入到 Postgres repository 中。

错误归一化

每个适配器将 SDK 特定异常归一化为服务级错误:ProviderRequestError(retryable)用于 LLM 和 embedding 失败。VectorStoreRequestError(retryable)用于 Qdrant 失败。WebSearchRequestError(retryable)用于 Tavily 失败。ObjectStorageConfigurationError 和 UploadVerificationError 用于 S3 失败。这些由 routers 或编排服务映射为 HTTP 状态码。

可观测性集成

observability.py 中的 provider_observation 用 Langfuse observation 包装每次 NVIDIA chat 和 embedding 调用。Context manager 接受 name、observation_type(generation/embedding)、model 和 metadata。Langfuse 禁用或不可用时 yield _NoopObservation,它静默接受 update() 调用。这确保追踪永不阻塞 provider 工作。

可靠性

幂等协调器

IdempotencyCoordinator 确保成本承载操作(ask、quiz)可以安全重试,不会产生重复的 provider 调用或持久化消息。

四态状态机

execute
Key 是新的或 pending 预约已被 abandon。调用者继续执行,必须调用 complete() 或 abandon()。
replay
此 user/operation/key/body 存在已成功的响应。返回缓存响应,不执行。
mismatch
存在相同 key 但不同 request_hash 的记录。抛出 IDEMPOTENCY_KEY_REUSED(409)。
in_progress
存在相同请求的 pending 预约。抛出 IDEMPOTENCY_REQUEST_IN_PROGRESS(409)。

请求哈希

request_hash(payload) 通过 model_dump(mode="json") 配合 sort_keys=True 和 separators=(",", ":") 规范化 Pydantic BaseModel,然后 SHA-256 哈希。这确保 body 一致性:相同 key 不同 body 是冲突,不是重放。

持久化

内存:LimitStoreMixin 将 idempotency_records 存储为 dict,键为 (user_id, operation, key),值为 state 和 response。PostgreSQL:IdempotencyPersistenceMixin 使用 INSERT ON CONFLICT DO NOTHING 进行原子预约,SELECT FOR UPDATE 检查重放,pg_advisory_xact_lock 串行化并发写入。Evidence repository 使用自己的 _lock_idempotency advisory lock。

Router 中的生命周期

routers/ask.py 和 routers/quiz.py 都遵循相同模式:构造 IdempotencyCoordinator,调用 begin(),若 replay 不为 None 则返回,否则执行 service,成功时调用 complete(),失败时调用 abandon()。MCP ask_grounded tool 遵循相同模式。Evidence 端点使用类似的 _idempotency() 校验和 _store_call() 错误映射流程。
