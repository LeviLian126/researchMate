Worker . workers/ai-worker

The ResearchMate AI worker is a Celery application that executes 6 durable tasks across 5 queues, supervised by 3 process roles in combined deployment. It owns document ingestion and parsing, LangGraph evidence workflows with human-in-the-loop review, outbox-to-Celery dispatch, RAGAS-backed evaluation, lease-protected deletion, and fault simulation. This page walks through every source file in workers/ai-worker/src/researchmate_worker/.

Technology stack fundamentals

8 foundations that power the worker

Each card explains what the technology does in general and how the worker uses it specifically.

Celery

Distributed task queue framework. celery_app.py creates the Celery application with task_acks_late=True, task_reject_on_worker_lost=True, worker_prefetch_multiplier=1, and task_track_started=True. Six tasks are registered in tasks.py with bounded max_retries (3-8) and exponential backoff. The combined supervisor runs one solo-pool worker consuming all 5 queues.

LangGraph

Stateful graph orchestration library. evidence_graph.py builds a 6-node StateGraph (plan, retrieve_and_extract, reconcile, human_review, synthesize, validate_and_commit) with conditional fan-out via Send. Checkpoints persist to PostgreSQL via PostgresSaver with JsonPlusSerializer(pickle_fallback=False). The interrupt() primitive pauses for human review without try/except wrapping.

RAGAS

Retrieval-augmented generation evaluation framework. evaluation_scoring.py uses the Ragas 0.4 collections API (Faithfulness metric) backed by an OpenAI-compatible NVIDIA AsyncOpenAI client. The scorer runs inside asyncio.run() and produces a MetricScore with pass threshold 0.8. Three deterministic metrics (schema_valid, citation_precision, evidence_recall) are computed without an LLM judge.

Docling + pypdf

Document parsing adapters. parsing.py implements DoclingDocumentParser, a resource-aware parser that reserves Docling's visual pipeline for PDFs and falls back to pypdf for lightweight text extraction. DOCX and PPTX are parsed via stdlib zipfile + ElementTree with zip-bomb guards. The active backend is selected by pdf_parser_backend (pypdf or docling).

Qdrant

Vector database for chunk indexing and retrieval. ingestion_service.py calls QdrantHybridStore.upsert_chunks() to project parsed chunks into the vector store. workflow_execution.py queries Qdrant with owner-scoped filters (user_id, project_id, source_type) for evidence retrieval. The rerank collection supports late-interaction models with configurable dimension (default 96).

torch

Deep learning runtime required by Docling's visual PDF pipeline. When pdf_parser_backend is set to docling, DocumentConverter loads vision models backed by torch. In pypdf mode, torch is never imported. The worker runs with --pool=solo to avoid Celery fork-safety issues with torch and the GIL-bound converter.

Outbox pattern

Durable event delivery without dual-write inconsistency. outbox.py defines SqlOutboxStore with FOR UPDATE SKIP LOCKED batch claiming, at-least-once publishing via CeleryTaskPublisher, and exponential backoff on failure: min(300, 2^min(attempts, 8)). dispatch_outbox.py runs a dedicated polling process that drains pending events into Celery task deliveries.

Lease concurrency control

Expiring job leases prevent duplicate work across worker instances. Every claim() atomically sets lease_owner and lease_expires_at via UPDATE ... RETURNING. If a worker crashes, the lease expires and another worker reclaims the job. Deletion blocks on running ingestion leases; workflow delivery supports safe re-delivery via claim_delivery() idempotency.

Configuration & entry points

The four files that bootstrap the worker

These files own configuration validation, the Celery application, task registration with bounded retry, and the builder functions that construct provider-backed services at process boundaries.

config.py . WorkerSettings

A pydantic-settings BaseSettings class validating every worker knob before any managed dependency is constructed. Key groups: runtime limits (worker_soft_time_limit_seconds=840, worker_time_limit_seconds=900), outbox (outbox_batch_size=50, outbox_max_attempts=8), ingestion lease (ingestion_lease_seconds=1200, ingestion_max_attempts=5), parser (parser_pipeline_version="resource-aware-v4", parser_max_pages=300, pdf_parser_backend="pypdf" or "docling", docling_artifacts_path), workflow (workflow_pipeline_version="evidence-v1", workflow_lease_seconds=900, workflow_call_budget_reservation_usd=0.25, workflow_max_prompt_tokens=32768, langgraph_strict_msgpack=True), LLM (nvidia_model="z-ai/glm-5.2", llm_temperature=1.0, llm_max_tokens=16384, llm_seed=42), embedding (nvidia_embedding_model="nvidia/nv-embed-v1", embedding_dimension=4096), Qdrant (v3 collection, named BM25 sparse model, native-hybrid rollout flag, rerank collection/model), web search (tavily), observability (langfuse), and object storage (R2 or generic S3 with auto region). A model_validator(mode="after") enforces that preview/production require DATABASE_URL, REDIS_URL, object storage, NVIDIA LLM + embedding, Qdrant, Tavily, Langfuse, strict LangGraph serialization, and offline Docling artifacts when docling backend is active.

celery_app.py . create_celery_app()

Creates the Celery application with broker_url from REDIS_URL (or memory:// for tests). Critical settings: task_acks_late=True (acks only after successful execution), task_reject_on_worker_lost=True (re-queue on crash), worker_prefetch_multiplier=1 (one task at a time), task_track_started=True, task_ignore_result=True (no result backend). The task_routes dict maps 6 task names to 5 queues: ingest_document to ingestion, delete_document and delete_project to deletion, run_workflow to workflow, run_evaluation to evaluation, run_fault_simulation to reliability. Broker visibility_timeout is set to worker_time_limit_seconds * 2. Three Celery signals (worker_ready, heartbeat_sent, worker_shutdown) write bounded heartbeat metadata to the runtime_heartbeats table via record_heartbeat, with a configurable throttle (runtime_heartbeat_seconds, default 30).

tasks.py . 6 tasks + 4 _mark_* terminal functions

Registers six @celery_app.task decorators with bind=True and bounded max_retries. Each task validates its event payload (Pydantic model_validate), constructs the service via a builder function, and delegates execution. On retryable failure, the backoff formula is min(300, 2^min(retries+1, 8)). On non-retryable or bootstrap failure, one of 4 _mark_* terminal functions marks the job/run as failed in the database so an explicit retry can recover it: _mark_job_bootstrap_failed (ingestion + deletion jobs, also marks documents as failed), _mark_workflow_bootstrap_failed (workflow runs), _mark_evaluation_run_failed (evaluation runs), _mark_fault_exercise_failed (fault exercises). The run_workflow task is the most complex: it acquires a delivery lease, constructs a PostgresSaver checkpointer with JsonPlusSerializer(pickle_fallback=False), and handles three invocation modes (resume via Command, resume from checkpoint, or fresh initial_state).

task_builders.py

Defines three task event models (WorkflowTaskEvent, EvaluationTaskEvent, FaultSimulationTaskEvent) and six builder functions. build_ingestion_service (lru_cached) constructs DocumentIngestionService with SqlIngestionStore, S3CompatibleObjectStorage, DoclingDocumentParser, and QdrantHybridStore. build_deletion_service and build_project_deletion_service (both lru_cached) construct deletion services with the same adapter stack. build_workflow_domain constructs SqlEvidenceWorkflowDomain with a BudgetedChatProvider wrapping NvidiaChatProvider. build_evaluation_runner constructs EvaluationRunner with QdrantCaseExecutor and RagasFaithfulnessScorer. build_fault_simulation_service constructs FaultSimulationService with just a database engine. Each builder validates required settings before constructing adapters, raising RuntimeError with a descriptive message if a managed dependency is missing.

Document ingestion . 7 files

Ingestion file-by-file breakdown

The ingestion pipeline downloads an object, parses it, projects deterministic chunks and pages, upserts vectors, and transitions the job to ready. Every step is lease-protected.

ingestion_models.py
Defines the data contracts. IngestionEvent (Pydantic BaseModel) validates job_id, user_id, project_id, document_id. IngestionRecord (frozen dataclass) carries claimed document metadata. ParsedBlock carries normalized text with structural provenance (page_no, slide_no, section_title, metadata). PageProjection carries page-level text for durable source display. ParserAdapterError and IngestionFailure normalize failures with stable codes and retryable flags. Four Protocol classes define adapter boundaries: DocumentParser, ObjectReader, VectorProjection, IngestionStore.
ingestion_service.py
DocumentIngestionService.handle() orchestrates the full pipeline: claim the job lease, download the object to a TemporaryDirectory, verify size and SHA-256 checksum, parse into ParsedBlock list, project to pages + chunks via build_projections, replace_content in SQL, mark_ready. For long documents, after Qdrant upsert the _compile_overview_wiki() method invokes WikiCompiler.compile_overview() to append an Overview Wiki chunk (has_vector=False) to the RAG chunks; the appended list is persisted via replace_content, which writes mixed has_vector chunks. Failures are classified: ObjectStorageRequestError and VectorStoreRequestError are retryable; ParserAdapterError respects its retryable flag; IngestionFailure passes through; all other exceptions become INGESTION_INTERNAL_ERROR (non-retryable). The _record_failure method chooses mark_retryable (if retryable and attempts < max) or mark_failed.
ingestion_store.py
SqlIngestionStore implements all IngestionStore protocol methods. claim() atomically transitions a pending or expired job to running via UPDATE ... RETURNING, sets the lease, and marks the document as parsing. The query joins jobs, documents, and projects to enforce owner scope, active project status, and non-deleted document. replace_content() acquires SELECT FOR UPDATE on job + document + project, deletes old pages and chunks, inserts new ones with qdrant_point_id = str(chunk.id), and transitions the document to indexing. mark_ready() transitions job to succeeded and document to ready. mark_retryable() and mark_failed() release the lease with appropriate status.
ingestion_projections.py + ingestion_chunking.py
build_projections() transforms ParsedBlock list into (PageProjection list, ChunkEntry list). The structure-aware chunker never crosses a page, slide, or section boundary, overlaps complete semantic units instead of arbitrary characters, and records section title/path/index plus stable character offsets. Page and chunk IDs are deterministic UUID5 values derived from the normalized locator-section stream, pipeline version, and content hash. Re-ingestion therefore stays idempotent while stale vector points are removed only after replacement upserts succeed.
parsing.py
DoclingDocumentParser is resource-aware. For PDFs, _parse_pdf_lightweight uses pypdf's PdfReader with strict=False and page-limit enforcement. If pdf_backend is docling, _pdf_converter lazily loads DocumentConverter with PdfPipelineOptions(artifacts_path, enable_remote_services=False). DOCX parsing reads word/document.xml via _read_bounded_xml with a streaming zip-bomb guard (max_xml_bytes). PPTX parsing discovers slide XML members via regex, sorts by slide number, and extracts paragraph text. All blocks carry metadata with parser_name, parser_version, source_item_ref, source_ordinal, source_label, and source_anchors.
parsing_helpers.py
Three pure functions. _normalized_archive_member() normalizes zip member paths (backslash to forward slash, strip leading slash, casefold). _package_version() reads package version via importlib.metadata, returning "unknown" if not found. _serialize_provenance() converts Docling item provenance (item.prov) into anchor dictionaries with item_ref, locator_kind, page_no, bbox, and charspan. Falls back to a structural anchor if no provenance exists.
jobs.py
chunk_text_for_index(text, target_size=900) is a pure function that splits normalized text into bounded chunks. It strips blank lines, joins paragraphs, and accumulates text until target_size is exceeded, then starts a new chunk. No content is dropped. Shared by the worker and the API adapter for test reuse.

Outbox dispatch . 2 files

Outbox file-by-file breakdown

The outbox pattern bridges the API's transactional writes and the worker's Celery task deliveries, preserving at-least-once semantics without dual-write inconsistency.

outbox.py
Defines the outbox infrastructure. ClaimedOutboxEvent (frozen dataclass) carries one leased event. OutboxStore Protocol defines claim, mark_published, mark_failed, requeue_stale. TaskPublisher Protocol defines publish. OutboxDispatcher orchestrates batch publishing: dispatch_once() claims a batch (FOR UPDATE SKIP LOCKED, limit=batch_size), publishes each event, and marks the outcome. recover_stale_claims() requeues events stuck in publishing status older than 15 minutes. SqlOutboxStore implements all transitions with atomic SQL. CeleryTaskPublisher maps 7 event types to 6 Celery task names via TASK_BY_EVENT, routing to the correct queue (deletion, workflow, evaluation, reliability, or ingestion default). The mark_failed delay uses min(300, 2^min(attempts, 8)).
dispatch_outbox.py
Entry point for the dedicated dispatcher process. build_dispatcher() constructs OutboxDispatcher with SqlOutboxStore and CeleryTaskPublisher from WorkerSettings. main() parses --once and --poll-seconds arguments, calls recover_stale_claims() on startup, then loops: record a dispatcher heartbeat, call dispatch_once(), sleep if no events were published. This process is one of the three child processes supervised by render_combined.py.
At-least-once delivery: The API writes outbox_events within the same transaction as its domain changes. The dispatcher claims events with FOR UPDATE SKIP LOCKED, publishes them as Celery tasks with the event's idempotency_key as task_id, and marks them published. If the worker crashes after publishing but before marking, the event is requeued and re-delivered. Idempotent claim() and lease logic in each service makes re-delivery safe.

LangGraph workflow . 9 files

LangGraph file-by-file breakdown

The evidence workflow is a 6-node LangGraph StateGraph that plans research questions, retrieves and extracts claims, reconciles relationships, optionally pauses for human review, synthesizes a report, and atomically commits to 8 database tables.

evidence_graph.py
Defines EvidenceWorkflowState (TypedDict, total=False) with 24 fields carrying checkpoint-safe state. EvidenceWorkflowDomain Protocol defines 7 application decision methods. build_evidence_graph() constructs the StateGraph lazily (deferred import of langgraph). The graph has 6 nodes: plan, retrieve_and_extract, reconcile, human_review, synthesize, validate_and_commit. plan uses conditional_edges with a fan_out function that creates one Send per question, enabling parallel retrieval. human_review wraps interrupt() without try/except so LangGraph can persist and surface it. Edges: START to plan, plan fans out to retrieve_and_extract, retrieve_and_extract to reconcile, reconcile to human_review, human_review to synthesize, synthesize to validate_and_commit, validate_and_commit to END.
workflow_core.py
SqlEvidenceWorkflowDomain inherits WorkflowExecutionMixin, WorkflowCommitMixin, WorkflowEventsMixin. Owns the engine, provider, vector_store, pipeline_version, and optional web_search. bind_run() attaches run context to BudgetedChatProvider. initial_state() validates ownership and pipeline configuration (WorkflowPipelineConfig), handles report_refresh kind by validating base report and impacted sections, and constructs the initial EvidenceWorkflowState. claim_delivery() acquires an expiring delivery lease (supports pending, running, waiting_human statuses). release_delivery() releases only the current worker's lease. record_retry() logs retry intent as a run_event without marking the run terminal.
workflow_execution.py
WorkflowExecutionMixin provides provider-facing decisions. plan() creates research questions via build_research_plan or preserves exact refresh sections. retrieve_and_extract() queries Qdrant with owner-scoped filters, optionally extends with web search (Tavily), deduplicates chunks, and extracts claims via extract_claims. reconcile() derives claim relationships via reconcile_claims. review_payload() requests human review only when confidence < 0.75 or untrusted sources are detected (web pages, prompt-injection markers). apply_decision() applies approve/edit/reject decisions. synthesize() builds a ReportProposal via synthesize_report. validate_and_commit() rejects ungrounded claims before calling _commit. resume_value() loads one persisted human decision. mark_failed() makes a workflow failure terminal and releases the lease.
workflow_commit.py
WorkflowCommitMixin (inherits WorkflowEvidenceLoaderMixin) persists one workflow outcome within a single transaction. _commit() writes to 8 tables: ask_runs (linking the workflow to the ask run), research_questions, citations, claims (with incremental source_version), claim_evidence, claim_relations, reports (with revision number), and report_sections. For report_refresh, it validates that generated sections exactly match impacted sections, replaces only those sections, preserves unchanged sections, and invalidates the base report. A pg_advisory_xact_lock on the project serializes commits so claim versions and report revisions stay unique.
workflow_events.py
WorkflowEventsMixin provides structured event writes. _node_started() records a node_started event with progress. _node_completed() records a node_completed event with progress and payload. _event() is the shared static method that acquires pg_advisory_xact_lock(hashtextextended(run_id)) and inserts a run_event with an auto-incrementing sequence via coalesce(max(sequence)+1).
workflow_loader.py
WorkflowEvidenceLoaderMixin provides _load_chunks(), which resolves evidence referenced by workflow state via owner- and project-scoped SQL queries. It selects chunks by user_id, project_id, and chunk_id list, preserving the original order and filtering out missing IDs. This ensures the workflow never widens its ownership scope when loading evidence.
workflow_models.py
Defines WorkflowRuntimeError (RuntimeError with code and retryable attributes). WorkflowPipelineConfig (Pydantic BaseModel) validates retrieval_limit (1-50), model, and evidence_prompt_version (pattern: evidence-review-v[0-9]+). _json() is a compact JSON serializer with ensure_ascii=False and default=str.
workflow_runtime.py
SqlEvidenceWorkflowDomain subclass preserves the historical import path and monkeypatch seam for workflow orchestration clients. Overrides synthesize() to maintain the public synthesis seam used by tests. Re-exports build_research_plan, extract_claims, reconcile_claims, synthesize_report from researchmate_api.services.evidence_generation.
budget.py
BudgetedChatProvider wraps a ChatProvider delegate with per-call USD reservation and prompt token limits. bind_run() attaches the run_id. complete() estimates prompt tokens (len/4+1), rejects if over max_prompt_tokens (WorkflowBudgetExceeded), atomically reserves budget_reserved_usd against budget_limit_usd, calls the delegate, and records actual cost + latency + token usage in run_events. _reserve() uses UPDATE ... WHERE budget_reserved_usd + amount <= budget_limit_usd RETURNING to atomically check and reserve.
8-table atomic commit: _commit writes to ask_runs, research_questions, citations, claims, claim_evidence, claim_relations, reports, and report_sections in a single transaction. This ensures a workflow outcome is either fully persisted or fully rolled back, with no partial reports or orphaned claims.

Deletion . 3 files

Deletion file-by-file breakdown

Deletion removes remote artifacts (Qdrant points, S3 objects) before marking the durable job complete. Document deletion and project deletion are split by aggregate but share the same lease and retry semantics.

deletion_models.py
Defines data contracts. DocumentDeletionEvent and ProjectDeletionEvent (Pydantic) validate job_id, user_id, project_id (and document_id for documents). DeletionRecord and ProjectDeletionRecord (frozen dataclasses) carry claimed artifacts. Four Protocol classes: DeletionStore (claim, mark_ready, mark_retryable, mark_failed), ObjectDeletion (delete), VectorDeletion (delete_points, delete_project_points), ProjectDeletionStore.
deletion_document.py
SqlDeletionStore.claim() first fails any running ingestion job for the same document (DOCUMENT_DELETING), then atomically claims the deletion job via UPDATE ... RETURNING with a NOT EXISTS guard against active ingestion leases. If blocked, raises IngestionFailure("DOCUMENT_INGESTION_RUNNING", retryable=True). mark_ready() acquires SELECT FOR UPDATE, deletes document_pages and chunks, transitions deletion_jobs and jobs to succeeded. DocumentDeletionService.handle() claims, deletes Qdrant points, deletes the S3 object, and marks ready. Failures are classified as OBJECT_DELETE_UNAVAILABLE, VECTOR_DELETE_UNAVAILABLE, or DELETE_INTERNAL_ERROR.
deletion_project.py
SqlProjectDeletionStore.claim() fails all pending/running ingestion jobs for the project, then claims the project deletion job. The RETURNING clause aggregates all r2_object_keys and qdrant_point_ids for the project via subqueries. mark_ready() nullifies job foreign keys, hard-deletes the project row, and transitions jobs. ProjectDeletionService.handle() claims, deletes all Qdrant project points, deletes each S3 object key, and marks ready. Same retry/failure classification as document deletion.

Evaluation . 7 files

Evaluation file-by-file breakdown

The evaluation system runs lease-protected regression tests against frozen datasets, scoring grounded answers with deterministic metrics and an optional RAGAS faithfulness judge.

evaluation_models.py
Defines immutable data contracts. PipelineRuntimeConfig (Pydantic) validates retrieval_limit, model, evaluation_prompt_version (pattern: grounded-answer-v[0-9]+), retrieval_mode. EvaluationCase (frozen dataclass) carries one dataset case with input, expected_output, expected_evidence. PipelineResult carries the generated answer, contexts, retrieved and cited chunk IDs. MetricScore carries one metric outcome with name, version, value, passed, details, judge_model. ClaimedEvaluation carries the lease-protected run policy. EvaluationRuntimeError has code + retryable. Two Protocols: CaseExecutor, FaithfulnessScorer. SUPPORTED_METRICS = {schema_valid, citation_precision, evidence_recall, faithfulness}.
evaluation_executor.py
QdrantCaseExecutor.execute() applies the production retrieval planner before querying owned Qdrant chunks (owner-scoped, LOCAL_DOC source type), so evaluation exercises exact, semantic, and balanced-hybrid weighting instead of a hard-coded vector query. It validates the provider model and prompt version, calls build_llm_grounded_answer, and returns response, contexts, retrieved_chunk_ids, and cited_chunk_ids.
evaluation_persistence.py
EvaluationPersistenceMixin provides lease-safe database operations. _claim() leases a pending or expired evaluation run, validates accepted pipeline version, loads metrics from summary, enforces metric subset of SUPPORTED_METRICS, and constructs ClaimedEvaluation with bounded max_parallelism (1-20, default 4). _load_cases() loads frozen cases joined to the run's dataset. _completed_case_ids() identifies cases with all requested metrics already durable. _reserve_case_budget() atomically reserves per-case USD without crossing the cap. _save_scores() persists scores with lease verification and ON CONFLICT DO UPDATE. _complete() builds a regression summary comparing current metrics with the latest succeeded baseline run.
evaluation_runner.py
EvaluationRunner (inherits EvaluationPersistenceMixin) coordinates bounded parallel evaluation. run() claims the lease, loads cases, filters completed cases, then uses ThreadPoolExecutor(max_workers=claimed.max_parallelism) to execute pending cases in parallel. Each case reserves budget, executes via the CaseExecutor, scores with deterministic_scores + optional faithfulness, and saves scores. Retryable failures are collected; if attempts < max_attempts, the run is released for retry. Otherwise, permanent failures are counted and _complete() finalizes the run with a regression summary.
evaluation_scoring.py
deterministic_scores() computes three reproducible metrics without an LLM: schema_valid (response non-empty + has citations), citation_precision (cited AND retrieved / cited), evidence_recall (expected AND retrieved / expected, pass threshold 0.8). RagasFaithfulnessScorer uses the Ragas 0.4 collections API (Faithfulness metric) with an AsyncOpenAI client backed by NVIDIA, running inside asyncio.run(). Pass threshold is 0.8. Raises RAGAS_NOT_INSTALLED if ragas is not importable.
evaluation_summary.py
build_regression_summary() compares current metric aggregates with a baseline run, computing mean_delta and pass_rate_delta per metric. Regression is detected when mean_delta < -0.02 or pass_rate_delta < -0.05. The summary includes completed_cases, failed_cases, execution_succeeded, quality_passed, metric_summary, baseline_comparison, regressed_metrics, and budget tracking. _metric_aggregates() queries evaluation_scores grouped by metric_name. _safe_evaluation_error() classifies exceptions by code and retryable attribute, defaulting to non-retryable rather than string-matching class names. json_dumps() is a compact serializer for SQL writes.
evaluation.py
Stable facade. Re-exports all public symbols from evaluation_executor, evaluation_models, evaluation_runner, evaluation_scoring, and evaluation_summary. Provides a single import surface for task_builders.py.

Reliability . 1 file

Fault simulation

fault_simulation.py records bounded failure/recovery exercises without mutating any provider, workflow run, or external service.

fault_simulation.py . FaultSimulationService

A non-mutating reliability validator. SCENARIO_BOUNDARIES maps 4 scenarios to boundary names: llm_timeout (chat_provider_timeout_boundary), qdrant_unavailable (vector_projection_unavailable_boundary), worker_interrupt (lease_recovery_boundary), r2_failure (object_storage_failure_boundary). run() claims one exercise via UPDATE ... RETURNING with lease and attempt guards, looks up the boundary, snapshots the optional target workflow run, and persists a safe_result with simulation_only=True, external_calls=0, injected_boundary, simulated_transition, recovery_state, and target_snapshot. Unsupported scenarios fail with FAULT_SCENARIO_UNSUPPORTED. The entire claim-snapshot-complete cycle is one short transaction so a database failure rolls back and the task remains safely replayable.

Process supervision . 2 files

Combined deployment and runtime health

render_combined.py supervises 3 child processes; runtime_health.py persists non-secret liveness signals consumed by the public readiness probe.

render_combined.py

The combined process supervisor for single-container deployment. child_commands() declares 3 supervised commands: (1) uvicorn serving researchmate_api.main:app on the configured port with proxy headers, (2) celery worker with -A researchmate_worker.celery_app:celery_app, --queues=ingestion,deletion,workflow,evaluation,reliability, --pool=solo, --concurrency=1, (3) python -m researchmate_worker.dispatch_outbox. apply_schema_migrations() optionally runs migrations before any process starts (RUN_SCHEMA_MIGRATIONS=1). backfill_qdrant_rerank() optionally provisions the rerank collection (RUN_QDRANT_RERANK_BACKFILL=1). wait_for_api() polls /api/v1/healthz until 200 before starting workers (timeout 240s). Signal handlers forward SIGTERM and SIGINT to all children. The supervisor polls child exit codes every 0.5s and propagates failures.

runtime_health.py

record_heartbeat() upserts a non-secret liveness signal into the runtime_heartbeats table. The INSERT ... ON CONFLICT (component) DO UPDATE writes component, instance_id (defaults to socket.gethostname()), status, safe_metadata (JSON), and updated_at. Called by celery_app.py signal handlers for worker ready/heartbeat/shutdown, and by dispatch_outbox.py on each poll cycle. The metadata payload is bounded and non-secret (e.g., {"queues": "ingestion,deletion,workflow,evaluation,reliability"} or {"poll_seconds": 2.0}).

Ingestion slice

Document ingestion . 7-step proof chain

From the outbox event arriving as a Celery task to the document transitioning to ready, every function the delivery passes through:

1. Event validationtasks.py: IngestionEvent.model_validate(event) validates job_id, user_id, project_id, document_id
2. Lease claimingestion_store.py: SqlIngestionStore.claim() atomically transitions job to running via UPDATE ... RETURNING, sets lease_owner + lease_expires_at, marks document as parsing
3. Object downloadingestion_service.py: S3CompatibleObjectStorage.download_to_file() writes to a TemporaryDirectory; size checked against max_upload_bytes
4. Checksum verifyingestion_service.py: SHA-256 of downloaded bytes compared to record.checksum_sha256; mismatch raises CHECKSUM_MISMATCH (non-retryable)
5. Parseparsing.py routes 42 file types: lightweight PDF, bounded OOXML for DOCX/PPTX/XLSX, visible HTML, notebook input cells, and decoded text blocks. Every path returns provenance-aware list[ParsedBlock].
6. Projectingestion_projections.py: build_projections() derives deterministic UUID5 page + chunk IDs from content_hash; jobs.py chunk_text_for_index splits text
7. Lightweight or vector indexingestion_service.py: is_lightweight_corpus() sums chunk tokens; at or below lightweight_token_threshold (4000) skips Qdrant upsert (has_vector=False); long documents upsert to QdrantHybridStore.upsert_chunks() (has_vector=True) before the Overview Wiki is appended.
8. Wiki compilationShort docs (≤4000 tokens): WikiCompiler.compile() transforms chunks into structured wiki pages (titles, [[wikilinks]], source provenance) — these pages replace the raw chunks. Long docs: _compile_overview_wiki() invokes compile_overview() to produce a single overview page that is appended to the RAG chunks (does not replace them). compile_overview() calls _sample_for_overview() to fit the WIKI_OVERVIEW_MAX_INPUT_TOKENS (6000) budget and _build_overview_prompt() for the LLM prompt; it returns [] on failure so RAG chunks are unaffected.
9. Persist + readyingestion_store.py: replace_content() writes pages + the mixed has_vector chunk list (RAG chunks plus appended overview Wiki chunk for long docs) using SELECT FOR UPDATE; mark_ready() transitions job to succeeded + document to ready.
Retry backoff: On retryable failure, the task re-raises with countdown = min(300, 2^min(retries+1, 8)). The exponential term is capped at 2^8=256, and the overall delay is capped at 300 seconds. Non-retryable failures call _mark_job_bootstrap_failed or mark_failed to make the job terminal.

LangGraph workflow slice

Evidence workflow . 6-node proof chain

From the workflow task claiming its delivery lease to the 8-table atomic commit, every node the graph executes:

1. planworkflow_execution.py: build_research_plan() via LLM; for report_refresh, preserves exact impacted section keys. Emits questions list. Progress: 5 to 15.
2. retrieve_and_extractworkflow_execution.py: Qdrant query (owner-scoped) + optional Tavily web search; extract_claims() via LLM. Fan-out: one Send per question. Progress: 20 to 45.
3. reconcileworkflow_execution.py: reconcile_claims() via LLM derives claim relationships. Progress: 50 to 60.
4. human_reviewevidence_graph.py: review_payload() checks confidence < 0.75 and untrusted sources; interrupt() pauses for human decision (approve/edit/reject). Skipped if no flags.
5. synthesizeworkflow_execution.py: synthesize_report() via LLM builds ReportProposal with sections. Progress: 70 to 85.
6. validate_and_commitworkflow_commit.py: rejects claims without evidence; _commit() atomically writes 8 tables (ask_runs, research_questions, citations, claims, claim_evidence, claim_relations, reports, report_sections). Progress: 90 to 100.
Checkpoint resumption: The run_workflow task handles three modes: (1) resume via Command(decision_id) when a human decision is submitted, (2) resume from existing checkpoint when get_tuple returns non-None, (3) fresh start via initial_state(). PostgresSaver with JsonPlusSerializer(pickle_fallback=False) ensures strict, portable checkpoints.

Outbox dispatch slice

Outbox dispatch . proof chain

From the dispatcher polling the outbox table to the Celery task being delivered, every step in the at-least-once pipeline:

1. Recover staledispatch_outbox.py: recover_stale_claims() requeues events stuck in publishing status older than 15 minutes back to failed
2. Claim batchoutbox.py: SqlOutboxStore.claim() selects pending/failed events with available_at <= now and attempts < max_attempts, using FOR UPDATE SKIP LOCKED, limit=batch_size
3. Publishoutbox.py: CeleryTaskPublisher.publish() maps event_type to task_name via TASK_BY_EVENT, routes to the correct queue, and calls celery_app.send_task() with idempotency_key as task_id
4. Mark publishedoutbox.py: SqlOutboxStore.mark_published() transitions status to published with published_at=now(), only if status is publishing
5. Mark failedoutbox.py: On publish exception, mark_failed() sets status=failed with safe_error (truncated to 200 chars) and available_at = now() + min(300, 2^min(attempts, 8)) seconds
7 event types to 6 task names: document.ingest.requested, document.delete.requested, project.delete.requested, workflow.run.requested, workflow.resume.requested (both map to run_workflow), evaluation.run.requested, fault.exercise.requested. Queue routing: deletion events to deletion queue, workflow events to workflow queue, evaluation events to evaluation queue, fault events to reliability queue, ingestion events to the configured ingestion queue.
