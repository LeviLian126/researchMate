ResearchMate 基础设施层定义持久化与协调设施：Supabase/PostgreSQL 是真相源，Qdrant 执行路由式 Hybrid 检索，生成的 OpenAPI 锁定 43 条路径上的 49 个操作。

技术栈基础

5 个基础设施组件

每张卡片说明该组件的通用职责,以及 ResearchMate 中的具体用法。

Supabase

PostgreSQL 托管平台,提供数据库、认证(auth.uid())、存储和 Edge Functions。ResearchMate 使用其 PostgreSQL 实例作为唯一真相源,所有业务表和协调表均在此创建。RLS 策略直接在数据库层强制多租户隔离。

PostgreSQL RLS

Row Level Security 在数据库层强制每行数据的访问控制。全部 31 张业务表均启用 RLS,通过 auth.uid() 实现按用户隔离。pipeline_versions 支持 developer/admin 角色策略,outbox_events 不设认证用户策略(仅 service-role)。

Database migrations

21 个 additive SQL 迁移按版本排序。最新迁移同步 document bucket MIME 类型;近期迁移还包括结构化 chunk 溯源、对话索引、human-decisions 去重、答题反馈评估实验室、扩展文件类型、chunk_has_vector、轻量无向量 chunk。

Qdrant collections

三种角色:保留 legacy retrieval 用于即时回滚,v2 执行 multivector late-interaction rerank,v3 影子集合存储命名 dense 与启用 IDF 的 BM25 向量。每个查询分支都重复 owner filter。

OpenAPI spec

49 个操作分布在 43 条路径和 12 个 tag 下，共有 71 个 component schema。openapi.yaml 由 FastAPI 确定性渲染，--check 会拒绝漂移。

Qdrant 配置详解

三个向量集合角色

researchmate_chunks 保留为回滚路径;researchmate_chunks_v2 执行 late-interaction rerank;researchmate_chunks_v3 是原生 BM25 影子检索目标。三者均强制 tenant 过滤。

researchmate_chunks (v1)

主检索集合,定义在 infra/qdrant/researchmate_chunks.json。支持 hybrid retrieval:dense 向量(4096 维,Cosine 距离)+ sparse 向量(IDF modifier),使用 RRF(Relative Reciprocal Fusion)融合排序。

迁移执行流程

apply_migrations.py proof chain

7 步验证链确保迁移安全、有序、可审计地应用。

1. Enforce unique prefixesmigration_files() 排序所有 .sql 文件,校验版本前缀(第一个下划线前的 YYYYMMDDNNN 部分)在整个集合中唯一。
2. Reject destructive contentvalidate_files() 对每个文件去空白,拒绝空迁移,阻止包含 DROP DATABASE 的文件(不区分大小写)。
3. Approval gateapply 路径需要环境变量 ALLOW_SCHEMA_APPLY=1。未设置时脚本立即退出,不触碰数据库。
4. Advisory transaction lockpg_advisory_xact_lock(726334129) 在当前事务内串行化迁移执行,防止并发运行。
5. Tracking table bootstrap如不存在则创建 researchmate_schema_migrations(version PK, checksum_sha256, applied_at),随后读取所有已应用记录。
6. Checksum verification对追踪表中已有的每个文件重新计算 SHA-256 并比较。任何漂移触发 RuntimeError,中止执行。
7. Apply and record未应用的迁移按序在事务内执行,然后连同 SHA-256 摘要插入追踪表。事务仅提交一次。
