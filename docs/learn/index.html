Monorepo structure

Project structure

ResearchMate is a monorepo (single repository, multiple projects) managed by npm workspaces for JavaScript/TypeScript packages and uv workspace for Python packages. All code, configuration, and documentation live in the same Git repository.

What is a monorepo? A monorepo is a strategy for managing multiple related projects in a single version-controlled repository. Advantages include shared configuration, unified version locking, and easier cross-project refactoring. ResearchMate's frontend (apps/web), backend API (apps/api), and AI Worker (workers/ai-worker) all live in the same repository.
apps/web/
Next.js frontend application deployed on Vercel. Contains page routes, React components, API client, and authentication logic.
apps/api/
FastAPI backend REST API providing 45 /api/v1 operations. Contains routers, Pydantic models, service orchestration, and PostgreSQL persistence layer.
workers/ai-worker/
Celery Worker + Outbox Dispatcher handling document parsing, vector indexing, LangGraph workflow, and evaluation. Deployed with the API in the same Render container.
packages/shared/
Shared TypeScript type contracts (contracts.ts), the authoritative source for API data shapes.
infra/
Infrastructure configuration: Supabase SQL migration files, Qdrant collection config, OpenAPI spec.
scripts/
Operational scripts: database migration runner, Qdrant rerank backfill, OpenAPI export, and more.
tests/
Python test suite (36 files) covering unit tests, HTTP integration tests, contract inspection, and release safety.
docs/
Browser-openable project documentation (HTML), the page you are viewing now.
.github/workflows/
GitHub Actions CI pipeline definition (ci.yml).
skill/
gstack development skill library, including land-and-deploy, qa, review, and other workflow skills.
npm workspaces (Node.js package management)

The root package.json declares "workspaces": ["apps/web", "packages/shared"]. All JS/TS dependencies are locked by the root-level package-lock.json, and the frontend and shared package reference each other via the workspace protocol.

uv workspace (Python package management)

The root pyproject.toml declares [tool.uv.workspace] members = ["apps/api", "workers/ai-worker"]. All Python dependencies are locked by uv.lock, and CI and Docker install with uv sync --frozen to strictly follow the lockfile.

End-to-end slice

The complete journey of an Ask request

From the user typing a question in the browser to receiving a cited answer, all files and modules the request passes through:

Browserchat-composer.tsx, use-chat-workspace.ts, api.ts (apiFetch + getAccessToken), supabase.ts (JWT), fetch()
FastAPI middlewaremain.py: CORS, attach_request_id (generate request_id + security headers)
Auth + DIdependencies.py: get_current_user (JWKS JWT verification), get_store / get_chat_provider / get_hybrid_store / get_reranker (read singletons from app.state)
Router + idempotencyrouters/ask.py (thin orchestration), services/idempotency.py (four-state machine: execute / replay / mismatch / in_progress)
Conversation scopeservices/query_conversation.py: validate project/conversation, load chunks, query_context.py (summary compression + token budget + cross-conversation memory)
Routed hybrid retrievalquery_planning.py selects full-context, exact, semantic, hybrid, or expanded-hybrid; Qdrant v3 executes named BM25 + NVIDIA 4096-dim dense branches with route-weighted RRF and mandatory owner filters.
Rerankservices/rerank.py: Qdrant native, NVIDIA ranking, Deterministic (three-way fallback), pack_chunks (token budget packing)
Answer generationservices/query_generation.py, answering.py: with evidence → LLM grounded (JSON schema validation + one repair); without evidence → chat or abstain
Persistence + responsestore.py / persistence/postgres.py (RLS parameter): save run/trace/messages, return AskResponse, middleware attaches headers, browser renders
Async path: After document upload, the API writes outbox_events, the dispatcher polls and dispatches, the Celery worker ingests (parse + chunk + vector), and Qdrant becomes ready. The next Ask retrieves evidence from the new document. This async chain passes through dispatch_outbox.py, tasks.py, ingestion_service.py, parsing.py, ingestion_projections.py, qdrant_store.py.
