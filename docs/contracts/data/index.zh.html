Postgres / Supabase 目标合约

数据库实体、字段、完整性和访问

本页记录了九个维护中的 SQL 迁移的字段级合约：15 个初始表、16 个增量领域表和一个仅后端的运维表。密封测试默认使用进程内内存；此回退不是本地集成环境。PostgreSQL 适配器和 worker 仓库已存在。Migration 009 添加了个人聊天拥有权、项目记忆元数据、对话附件和扩展的 quiz 枚举；云应用和认证 RLS 验证是发布门槛。

15 个初始领域表 16 个增量领域表 31 个领域表 + 1 个运维表已声明 受管开发 schema · 已应用，集成未验证

边界

模式状态和约定

主要租户键

user_id 和 project_id 划定项目、文档、分块、对话、运行、测验和作业的范围。

删除模型

依赖记录级联删除；部分运行引用使用 ON DELETE SET NULL ；项目/文档/对话还支持软删除。

运行时差距

Schema 存在不证明已应用迁移、活跃 RLS、持久 API 写入或生产保留。

附加工作流和评估表

十五个附加合约来自 202607150002_evidence_review_schema.sql；202607150005_evaluation_budget_and_fault_exercises.sql 添加了 fault_exercises，使领域总数达到 31 个表（15 个初始 + 16 个附加）。Migration 006 添加了一个仅后端的运维 runtime_heartbeats 表和工作流租约/预算字段；它不计为领域表。Migration 007–009 演进了统一聊天、运行时重排、个人附件、项目记忆和测验类型，但未添加领域表。Migration 009 已应用；认证的直接 RLS 事务和提供商切换并发仍是发布证据门槛。

存储拥有权：PostgreSQL 是业务状态的真值源。S3 兼容对象存储存储私有来源字节和解析器产物；Qdrant 存储可重建的稠密/稀疏投影；Redis 仅存储代理和短时协调状态。任何不可替代的业务事实不得仅存在于对象存储、Qdrant 或 Redis 中。
检查点边界：LangGraph Postgres 检查点表是 SDK 管理的基础设施，不是领域表。受保护的发布命令在部署前运行一次 SDK 拥有的模式；worker 不执行 DDL。线上运行 31947882320 在临时 PostgreSQL 上跨越 20 次进程重启演练中断/恢复，1000/1000 次成功。四个 schema 版本 9 的表也存在于隔离的 researchmate-dev Supabase 中，但该托管实例未用于本次基准。这四个表不计入 31 个领域表的计数。
