请求约定

认证、拥有权和错误

认证

GET /api/v1/healthz 和 GET /api/v1/readyz 对平台探针公开。其余所有 REST 操作均声明 HTTP bearer 认证。本地/测试模式仅接受具名或显式 dev: 身份；未知令牌直接拒绝。预览/生产环境需要 Supabase JWT 模式。2026 年 7 月 27 日，密码和 GitHub OAuth 身份从 Vercel 向 Live Render API 认证，各自在浏览器刷新后完成了拥有者范围内的项目创建/列表/读取，GitHub 用户对密码用户的 Library 收到了隐藏的未找到响应。会话过期/撤销和直接数据库 RLS 拒绝查询仍未经提供商验证。

拥有权

处理器解析 CurrentUser；Store 查找将资源限定在该用户范围内。缺失的资源和属于其他用户的资源均返回 404，以避免泄露标识符。

错误信封

运行时失败使用 {"error":{"code","message","request_id"}}。请求验证统一归为 VALIDATION_FAILED；验证/生成的请求 ID 通过 X-Request-ID 返回。

联邦身份规则。通过 Supabase Auth 添加 GitHub 不改变授权语义：已验证的 JWT sub UUID 是唯一的租户身份。电子邮件地址、GitHub 登录名、显示名称和提供商元数据绝不可用作拥有权判定依据。
已知 OpenAPI/运行时差异。OpenAPI 仍为部分 422 响应声明生成的 HTTPValidationError 体，而运行时处理器将验证统一归入项目错误信封。Ask 和 Quiz 还可能返回其 OpenAPI 响应映射中未包含的运行时 409 和 429 响应。

GET /api/v1/readyz — 检查非计费依赖就绪
调用方 / 访问
部署平台、就绪冒烟测试或操作员。公开；无需 bearer 令牌，无私有负载。
输入
无路径、查询或请求体字段。
成功
200，包含 status:"ready"、环境、组件状态和空的失败组件列表。本地/内存依赖可能为 not_required。
故障 / 语义
503，包含 status:"not_ready" 和安全的失败组件名称。它对 Postgres 执行 select 1，验证四个 SDK 拥有的检查点表，检查最新的 worker/dispatcher 心跳，拒绝过期或耗尽的 outbox 工作，ping Redis，并读取 Qdrant 集合元数据。S3 兼容对象存储、LLM 和 Web 搜索仍仅进行配置检查，因此不会消耗 NVIDIA 或 Tavily 配额。
当前边界
2026 年 8 月 1 日，后端修正 c5c89f5 上线 Live，公开存活检查和合并就绪检查均返回 HTTP 200；Postgres、Redis、Qdrant 集合访问、worker/dispatcher 心跳、outbox 状态和检查点表均已就绪。认证生产验收通过了普通聊天、文本层 PDF 上传/索引、有依据的回答和页面引用、Web 搜索、项目 Quiz 生成和通过前端修正 ce54452 的刷新恢复、对话删除和项目删除。

POST /api/v1/documents/{document_id}/complete — 验证上传并请求摄入
调用方 / 访问
文档拥有者。
输入
document_id：UUID。请求体可省略或为 null；当存在时，UploadCompleteRequest 接受可选的校验和和提取文本。
成功
202，包含 job_id 的对象。
故障 / 语义
404 DOCUMENT_NOT_FOUND；409 UPLOAD_SIZE_MISMATCH 或 UPLOAD_TYPE_MISMATCH；503 对象存储验证失败；422 验证失败；认证失败。内存仓库刻意保留同步提取文本回退。Postgres 仓库验证 S3 兼容元数据，然后原子性地写入解析状态、待处理任务和唯一 outbox 事件；重复完成请求返回现有任务。worker 在解析前验证可选的 SHA-256 校验和。
异步 / 恢复
outbox 分发器发布确定性任务 ID。Celery 消费者使用过期的 Postgres 租约、确定性的页面/分块 ID、有界重试和显式的 ready/failed 终态。生产文本层 PDF 路径达到 ready 并返回了页面引用。PDF 解析默认使用低内存的 pypdf；无文本层的扫描 PDF 以 PARSER_TEXT_LAYER_NOT_FOUND 终止，不会自动调用 Docling。

POST /api/v1/ask — 继续统一对话
调用方 / 访问
项目拥有者。当前本地配额为每用户每天 200 次 Ask 请求。
输入
严格 JSON AskRequest：项目 UUID、可选对话 UUID、消息和 web_enabled。未知或已弃用字段验证失败。
成功
200 AskResponse：对话和运行 UUID、回答、来源摘要、引用、trace UUID 和验证状态。

证据审查、评估、可靠性和 MCP 操作

生成的 OpenAPI 现包含 45 个 REST 操作，包括个人聊天引导、跨工作空间对话导航、对话范围附件、拥有者范围对话 CRUD 和两个运行时 rerank 操作。其路由、schema、拥有权/角色、幂等性和确定性仓库行为有代码证据；受管提供商、队列交付、检查点恢复、遥测导出和本次发布部署仍为集成未验证。MCP 是独立的协议边界，不计入 REST。

如何阅读各行： 请求和成功结构描述已实现的路由 schema。本地 LangGraph、RAGAS、严格检查点序列化器和 MCP 初始化测试现已通过。故障/恢复和验收行仍指明分布式系统门槛；它们不是受管检查点、提供商、队列或云运行时通过的证据。
