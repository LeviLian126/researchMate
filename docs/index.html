Project purpose

Portfolio scope

Portfolio objective

Demonstrate AI full-stack architecture, durable workflows, retrieval quality, data contracts, observability, failure recovery, security boundaries, and CI/CD with evidence an interviewer can inspect.

Explicitly outside the objective

Customer acquisition, revenue, pricing, subscriptions, billing, CRM, marketing automation, and growth analytics are not success criteria and will not drive the roadmap.

How to use these documents: recruiters can review the project scope, engineers can inspect the linked contracts and evidence, and demo users can exercise the system behavior. The project does not include a commercial conversion funnel.

Primary engineering scenario

From a source collection to an auditable evidence report

The primary scenario requires long-running ingestion, parallel evidence work, stateful review, incremental recomputation, and measurable quality. These requirements define the target architecture.

01 / INGESTBuild the source corpusUpload tens to hundreds of documents and web sources; parse, deduplicate, version, chunk, and index them asynchronously.
02 / PLANDecompose the research goalLangGraph turns a broad question into bounded sub-questions and persists checkpoints for interruption and resume.
03 / EXTRACTBuild an evidence modelCelery workers retrieve in parallel, extract claims, attach page-level citations, and classify support, conflict, duplication, and gaps.
04 / REVIEWResolve uncertaintyLow-confidence conclusions, untrusted web evidence, and prompt-injection signals pause for an explicit human decision.
05 / SYNTHESIZEPublish and update the reportGenerate a cited report and recompute only affected claims and sections when the corpus changes.
06 / PROVEEvaluate the systemCompare retrieval and pipeline versions; inspect traces, latency, tokens, cost, retries, failures, and recovery.

Active improvement tracks

Security, code quality, and test coverage in flight

These tracks are in active delivery, not yet shipped contract evidence. Status follows the Node08 rule: partial items name the missing proof that closes them; planned items name the dependency that unblocks the work.

HTTP rate limiting · in progress Security Hardening · API rate limiting

Slowapi integration against apps/api/.../main.py is being wired onto the FastAPI entrypoint with a configurable per-IP ceiling for the unauthenticated chat, file upload, and Quiz generation paths. Live proof is pending; the bounded ceiling must not regress warm chat latency or block the Playwright credential-free journey.

CSP and HSTS headers · in progress Security Hardening · Response headers

Content-Security-Policy and Strict-Transport-Security middleware is being added to the FastAPI response chain so the deployed site serves a strict TLS-only posture with explicit script/style/connect origins. Validation is pending against the public Vercel + Render hosts once the header surface is observable in production traffic.

Prompt injection guard · planned Security Hardening · LLM input safety

A server-side prompt-injection detector is being designed around the build_llm_chat_answer path so untrusted file and chat content cannot override system instructions. The guard will reject, redact, or escalate injected payloads before the bounded model call. Implementation and a red-team test set remain pending.

File content validation · planned Security Hardening · Upload safety

Server-side python-magic content sniffing is planned to reinforce the existing 25 MB PDF/DOCX/PPTX allowlist enforced by the private Supabase bucket, so an attacker cannot reach the parser with a mislabeled extension. The deployable reserve → signed PUT → HEAD → commit path remains the integration proof.

Pyright · basic mode configured Code Quality · Type checker

Project-wide pyright configuration is committed in pyproject.toml with typeCheckingMode = "basic", pythonVersion = "3.13", and include paths for apps/api, workers/ai-worker, and tests. CI now runs npm run check:types after the Python test step. Strict mode is intentionally off so the existing codebase migrates incrementally; tightening to per-file strict rules is an opt-in next step.

Pre-commit hooks · planned Code Quality · Local gate

A shared .pre-commit-config.yaml is planned to run Ruff, pyright (basic), OpenAPI drift, migration, and documentation checks before a commit is created, so the local gate mirrors the CI contract rather than catching issues only on push. Hook installation guidance and an opt-in enforcement plan remain pending.

Project AGENTS.md · planned Code Quality · AI guidance

A root AGENTS.md is planned to record the binding execution policy (hermetic local checks, no application or infrastructure services started locally), the bilingual documentation kanban convention, and the security and code-quality baselines that any AI agent must respect before editing the repository.
