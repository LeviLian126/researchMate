Local verification boundary

Hermetic checks only; integration runs after deployment

Execution policy: the local machine may run only the smallest relevant unit, domain, schema, contract, import, static, and build checks that do not require a locally hosted application or infrastructure service. Do not start Next.js, FastAPI, Celery, the outbox dispatcher, PostgreSQL, Redis, Qdrant, object storage, provider simulators, or Docker locally. Every modular or cross-service integration test runs against the authorized deployed/server environment with protected configuration and synthetic data.
Toolchains, not a local runtime topology

Node.js 22.14.0, npm 11.6.0, Python 3.13.2, uv, Celery, Docling 2.111.0/core 2.86.0, and Git are installed under the Windows project environment. Their presence permits hermetic checks; it does not authorize locally hosted application services.

Historical bounded proof

LangGraph 1.2.9, the Postgres checkpoint package, RAGAS 0.4.3, MCP 1.28.1, OpenTelemetry, and Langfuse are installed locally. Existing historical evidence covers fake-domain LangGraph fan-out, RAGAS imports, strict serializer import, and MCP initialization. It does not prove any database, queue, provider, telemetry, or deployed integration and is not a precedent for starting local services.

Forbidden local dependencies

No local PostgreSQL, Redis, Qdrant, object storage, provider endpoint, Vercel/Render runtime, Docker daemon, or application listener may be required to pass the local gate. A test that silently opens a listener or reaches a managed service belongs in the deployed integration suite.

Application processes run remotely

Next.js is exercised on Vercel. FastAPI, the Celery worker, and the outbox dispatcher are exercised in the combined Render service. Their real interactions with Supabase, Upstash, Qdrant, storage, identity, and providers are verified only from the deployed/server boundary.

Managed development services

The Supabase Free project is healthy, with automatic public-table exposure disabled and automatic RLS enabled. Render connects to the managed database and S3-compatible private bucket; Upstash, Qdrant, NVIDIA, Tavily, Langfuse, and OTLP configuration is loaded. Public readiness verifies PostgreSQL, Redis, worker/dispatcher heartbeats, outbox, checkpoints, and the Qdrant collection without charging providers. On 27 July 2026 a real Supabase session completed an owner-scoped project create/list/read round trip from Vercel through Render to PostgreSQL. Cross-user denial and deployed object/queue/vector/provider/telemetry workflows remain unvalidated.

Deployment topology and validation status

Recorded deployment state · 1 August 2026: backend correction c5c89f5 passed GitHub Actions run 30694324845 and became Live on Render; frontend correction ce54452 is deployed on Vercel Production. Public liveness and combined readiness return HTTP 200 with database, Redis, worker, dispatcher, outbox, checkpoint, and Qdrant ready. The authenticated Chrome journey passed chat, PDF, grounded citation, Web, Quiz generation/recovery, and deletion paths, and post-fix Render logs showed no new HTTP 500 or application ERROR.
Free-resource conclusion: Render Free is fixed at 0.1 CPU and 512 MB for this service, sleeps after inactivity, and does not provide horizontal scaling; there is no normal application path to request more capacity while staying on that plan. The current optimization therefore prioritizes fewer imports on the health-check critical path, complete-context short-circuiting for small corpora, bounded candidates, deterministic fallback, and one quality-qualified generation call. Oracle Always Free Ampere offers materially more zero-cost compute but adds VM patching, security, capacity, and migration work. Microsoft for Startups, Google for Startups AI, and GitHub Education are eligibility-based credit routes rather than guaranteed plan upgrades. Koyeb's free instance and Google Cloud's e2-micro do not clearly improve this combined Python workload enough to justify migration without a benchmark.
Frozen identity extension · no new application deployment: use one free GitHub OAuth App connected to Supabase Auth. GitHub authenticates; Supabase issues the JWT; the backend authorizes only by JWT sub. The callback is https://tjdkdganvszqawxspveg.supabase.co/auth/v1/callback. Google may be added later through the same boundary, but it is not required for the first release.
Privacy and encryption boundary: TLS protects transit; the private Supabase bucket and managed services protect stored data. The application additionally scopes PostgreSQL with API owner predicates plus RLS, object writes with an authenticated same-origin proxy and server-derived user/project/document keys, and Qdrant mutations/searches with mandatory user/project filters. Redis carries identifiers rather than document bytes and telemetry excludes raw content and secrets. This is deliberately not called end-to-end encryption: the Render worker must temporarily process plaintext for parsing and RAG. Per-object envelope encryption is deferred until a stricter threat model justifies key lifecycle complexity.

Frozen topology: Vercel web + one Render combined backendIt is the smallest change that preserves the implemented Next.js, FastAPI, Celery, and outbox boundaries. Existing Supabase, Upstash, and Qdrant resources avoid duplicate state services.Exactly two application deployments and zero required monthly fee, with cold starts, one failure domain, low concurrency, ephemeral local disk, free-resource suspension, and bounded parser capacity explicitly accepted.A selected free plan disappears; measured combined-process memory prevents readiness; or real users, real data, or an SLA require paid isolation.
Postgres is business truthWorkflow, evidence, report, decision, and evaluation state require transactions and integrity.S3-compatible object storage and Qdrant are rebuildable projections; Redis cannot own irreplaceable state.Measured access and scale invalidate the relational model.
Bounded LangGraph plus CeleryLangGraph owns durable decisions and state transitions; Celery owns parallel, retryable execution.Node and task idempotency plus shared run/event contracts are mandatory.One runtime can satisfy both orchestration and work execution with less complexity and equal proof.
No duplicate application deploymentDirect repository builds, direct OTLP export, and a combined demo container cover the current release boundary with fewer moving parts.The current plan keeps one web deployment and one combined backend service.A frozen-topology reopen trigger is met and the replacement is documented here before implementation.
GitHub OAuth reuses Supabase AuthA free GitHub OAuth App adds third-party login while preserving the existing issuer, JWT validation, and tenant identity.No new server is deployed. Authorization remains keyed only by JWT sub; Google is optional later and must reuse the same boundary.Supabase or GitHub can no longer meet the free-tier, account-linking, or isolation acceptance tests.
No production SLA claimFree tiers can cold-start, pause, throttle, or expire.The demo publishes quotas, readiness checks, and a read-only degraded mode.Paid resources and operational evidence support a measurable SLO.
