System architecture and deployment boundaries

This page defines the system boundaries and technology decisions. The selected free-tier topology uses Vercel Hobby for the web deployment and one Render Free Web Service for FastAPI, a Celery solo worker, and the outbox dispatcher. Vercel Production has been rebuilt with the managed API and Supabase public Auth configuration and renders the real sign-in boundary. A completed user login, RLS isolation, broker delivery, vector queries, charged provider calls, exported telemetry, and the complete durable workflow remain unvalidated.

Frozen free-tier deployment boundary

Two application deployments: Vercel web plus one combined Render runtime

Architecture decision · 25 July 2026: this is the selected public-demo topology. Cold starts, single-instance interruption, low concurrency, free-resource suspension, and bounded PDF support are accepted constraints.

Runtime and recovery flows

Runtime flows and failure ownership

1 · Asynchronous document ingestion and deletion code implemented · integration unvalidated
Reserve + uploadFastAPI validates ownership, type, size, and quota; the S3-compatible adapter issues a short-lived content-type-bound signed URL and verifies HEAD metadata.
Commit + dispatchPostgres writes document, job, and outbox intent atomically; the SKIP LOCKED dispatcher publishes a deterministic Celery task ID with backoff and stale-claim recovery.
Parse + indexA lease-protected task checks bytes/checksum, preserves Docling provenance, replaces deterministic page/chunk rows, and upserts named dense+sparse Qdrant vectors.
Delete + convergeA deletion consumer removes Qdrant/object-storage projections before database children using deterministic identifiers and retry. Managed-service crash, poison-work, stale-vector, and partial-delete convergence tests remain.
Recovery boundary: Postgres owns intent and lease state; workers own retryable processing. DOCX/PPTX smoke passed. PDF OCR/layout validation failed because its model download did not complete.

Local verification boundary

Hermetic checks only; integration runs after deployment

Execution policy: the local machine may run only the smallest relevant unit, domain, schema, contract, import, static, and build checks that do not require a locally hosted application or infrastructure service. Do not start Next.js, FastAPI, Celery, the outbox dispatcher, PostgreSQL, Redis, Qdrant, object storage, provider simulators, or Docker locally. Every modular or cross-service integration test runs against the authorized deployed/server environment with protected configuration and synthetic data.
Toolchains, not a local runtime topology

Node.js 22.14.0, npm 11.6.0, Python 3.13.2, uv, Celery, Docling 2.111.0/core 2.86.0, and Git are installed under the Windows project environment. Their presence permits hermetic checks; it does not authorize locally hosted application services.

Historical bounded proof

LangGraph 1.2.9, the Postgres checkpoint package, RAGAS 0.4.3, MCP 1.28.1, OpenTelemetry, and Langfuse are installed locally. Existing historical evidence covers fake-domain LangGraph fan-out, RAGAS imports, strict serializer import, and MCP initialization. It does not prove any database, queue, provider, telemetry, or deployed integration and is not a precedent for starting local services.

Forbidden local dependencies

No local PostgreSQL, Redis, Qdrant, object storage, provider endpoint, Vercel/Render runtime, Docker daemon, or application listener may be required to pass the local gate. A test that silently opens a listener or reaches a managed service belongs in the deployed integration suite.

Application processes run remotely

Next.js is exercised on Vercel. FastAPI, the Celery worker, and the outbox dispatcher are exercised in the combined Render service. Their real interactions with Supabase, Upstash, Qdrant, storage, identity, and providers are verified only from the deployed/server boundary.

Managed development services

The Supabase Free project is healthy, with automatic public-table exposure disabled and automatic RLS enabled. Render connects to the managed database and S3-compatible private bucket; Upstash, Qdrant, NVIDIA, Tavily, Langfuse, and OTLP configuration is loaded. Public readiness verifies PostgreSQL, Redis, worker/dispatcher heartbeats, outbox, checkpoints, and the Qdrant collection without charging providers. On 27 July 2026 a real Supabase session completed an owner-scoped project create/list/read round trip from Vercel through Render to PostgreSQL. Cross-user denial and deployed object/queue/vector/provider/telemetry workflows remain unvalidated.

Disallowed local gate

Do not run any development server, worker, dispatcher, database, broker, vector store, storage emulator, provider sandbox, or container. A fake adapter may run only in-process inside a hermetic test; it must not create a substitute local integration environment.

Required deployed integration gate

After deployment, verify public liveness/readiness, authenticated API behavior, RLS isolation, object lifecycle, queue delivery, worker/dispatcher heartbeats, Qdrant filtering, bounded provider calls, telemetry redaction, restart recovery, and the accepted browser journey. Record the deployed commit and environment with every result.

Privacy and encryption boundary: TLS protects transit; the private Supabase bucket and managed services protect stored data. Development target

Native Windows runs hermetic unit, contract, schema, import, static, and build checks only. It starts no application or infrastructure service and does not connect modules through managed resources.

Preview target

Vercel previews are supplied by the connected Git repository when a non-production deployment is created; no preview is evidence of the managed backend.

Public-demo target

Vercel Hobby remains the web host; one selected Render Free service is the only backend compute target. This free environment has no production SLA and must not hold real user data.

Readiness boundary

/api/v1/readyz checks Postgres, Redis, Qdrant, worker and dispatcher heartbeat freshness, outbox backlog, and LangGraph checkpoint tables; object storage/LLM/Tavily remain configuration-only to avoid charged probe calls. The managed endpoint returned HTTP 200 with no failed component on d7197f1.
